## 一、令牌方案（A 阶段）

### 1.1 为什么必须先令牌化（核心前提，复述并强化）

现状是**一个「令牌驱动」的浅色主题，但驱动得不够彻底**：

- `:root` 的 **18 个颜色令牌只覆盖了"语义色"**（表面 / 墨色 / 强调 / 语义三态 / 分隔），
- 而**结构色**（表格斑马纹、行 hover、选中行、面板遮罩、媒体上的半透明控件底、行内 code 底、阴影、焦点白隙）**全部是硬编码字面量**，且大量散在 `app.js` / `index.html` 的**内联 SVG** 里。

后果：**只加 `[data-theme="dark"]{...}` 覆盖这 18 个令牌，另有 209 处不会翻转** ⇒ 深色下白底白字、白块、发光焦点环、浅色图标。

> **A 阶段的唯一目标**：把这 209 处（其中 CSS 121 处）**收敛为语义令牌或声明豁免**，且**浅色模式逐像素零变化**。B 阶段才补 `[data-theme="dark"]`。

### 1.2 命名规则

沿现有风格（`--surface/--parchment/--pearl/--ink/--ink80/--ink48/--primary/--primary-bg/--hairline/--divider/--chipgray/--ok(-bg)/--err(-bg)/--warn(-bg)/--track`），并遵守：

1. **一物一名，禁止语义重叠**：不新增 `--white`（与 `--surface` 重叠）、不新增 `--gray`（与 `--parchment` 重叠）。
2. **角色后缀约定**：`-bg` = 该语义的**浅色底**；`-ink` = 该颜色**作为文字**时的取值；`-600/-700` = 色阶步进。
3. **成对的语义类（`.hl-*` / `.b-*`）不拆令牌**（见 §1.4.4 决策）：它们是"前景+底色"两值绑定，令牌化反而增加 12 个低复用令牌，改用 **dark-only 规则覆盖**更克制。
4. **"永远位于深色底上"的颜色不令牌化**（见 §1.4.6 豁免清单）：如 `.codebox`、`.copywrap.on-dark`、全屏查看器、`.toast` 底——它们在两个主题下**都不该变**，令牌化是纯噪音。

### 1.4 必须处理的特例（逐项给处置规则）

#### 1.4.1 `--focus` 值内的 `#fff`（`styles.css:30`）

```
--focus:0 0 0 2px #fff,0 0 0 4px var(--primary);   /* 白隙 + 主色 */
```
- **问题**：令牌**值里**含字面量 ⇒ 覆盖 `--primary` 也救不了它；深色下白隙变成"发光白圈"。
- **处置**：拆出 `--focus-gap`（浅色 `#fff` / 深色 `= --surface`），`--focus` 改为
  `0 0 0 2px var(--focus-gap),0 0 0 4px var(--primary)`。
- **深色效果**：2px 的底色隙 + 4px 主色环，靠"底色隙"把主色环与控件隔开——与浅色同一视觉语法，不发光。

#### 1.4.2 阴影（`--shadow-1/2` + 散落的 `rgba(0,0,0,.x)`）

#### 1.4.5 无图占位 / 音频占位（**已天然对称，无需改**）

`.acard .pic.no-pic .ph-ico{color:var(--ink);opacity:.26}`（450）、`.ap-thumb .ph-ico{color:var(--ink);opacity:.3}`（495）、`.asset-preview .empty-ph` 等：

- 用的是 **`--ink` + 半透明**，不是固定深色。浅色下 `--ink`=深⇒浅底上淡灰图标；深色下 `--ink`=浅⇒深底上淡白图标。**自动跟随，天然对称。**

- 唯一注意：hover 态 `.acard:hover .pic.no-pic{background:var(--primary-bg);border-color:var(--primary)}`（452）——深色下 `--primary` 用**实心蓝 `#0A6FD8`**（见 §2.2），边框可见度 3.47:1 ≥3 ✅。

## 三、主题切换机制（B 阶段）

### 3.1 三态：跟随系统 / 浅色 / 深色

**取值**：`auto`（跟随系统，默认）/ `light` / `dark`。

**"跟随系统"如何实现**（两选一，本文**推荐方案 B**）：

| 方案 | 做法 | 评估 |
|---|---|---|
| **A. 纯 CSS** | 不写 `data-theme`；用 `@media (prefers-color-scheme:dark){:root{...}}` | 简单，但**无法让用户显式覆盖**（一旦有 `[data-theme="dark"]` 覆盖，media 与属性选择器优先级打架，覆盖关系难维护） |
| **B. JS 解析后写 `data-theme`（推荐）** | 见下 | 单一事实来源，覆盖关系清晰 |

**推荐方案 B 的规则**：

1. **单一事实来源 = `document.documentElement`（`<html>`）上的 `data-theme` 属性**（`root` 令牌就在 `<html>` 上，`[data-theme]` 落同一元素最直观）。

   > 现有工程把令牌定义在 `:root`（= `<html>`）。**主题属性放 `<html>` 而非 `#app`**：因为 `.mask`/`.drawer`/`.recview`/`.pageview`/`.toasts` 都是 `#app` 的**兄弟/外部节点**（`index.html:94/97/136/154/218/…`），放在 `#app` 上它们拿不到。**这是必须遵守的结构约束。**

2. **解析流程（启动时，`bindStatic`/初始化早期，先于首帧渲染）**：
   - 读持久化值（§3.3）；无值则视为 `auto`。
   - `auto` ⇒ `const dark = matchMedia('(prefers-color-scheme:dark)').matches; html.dataset.theme = dark ? 'dark' : 'light'`。
   - `light`/`dark` ⇒ 直接写对应值（**用户显式选择优先于系统**）。
   - 同时挂 `matchMedia(...).addEventListener('change', ...)`：**仅当持久化值为 `auto` 时才响应**（否则用户的显式选择会被系统切换覆盖）。
3. **CSS 侧只需两条**：`:root{...浅色...}` 与 `[data-theme="dark"]{...覆盖...}`。**不写 `@media (prefers-color-scheme)` 进 CSS**（避免"媒体查询 vs 属性选择器"双源冲突）。
4. **防闪烁（FOUC）**：解析必须在首帧前跑。`index.html` 现有 `#app` 带 `hidden-view` 类、由 `setView()` 兜首屏——可在 `<head>` 末尾加一段**行内同步脚本**（早于 `app.js`），或在 `app.js` 顶部（模块执行期，早于 `bindStatic`）执行。**推荐前者**（`<head>` 内联 3 行读 localStorage 写 `data-theme`，杜绝刷新闪白）。

### 3.3 持久化

**关键事实（纠正简报）**：**全仓库 `app/` + `server/` 目前 `localStorage`/`sessionStorage` 用量 = 0**（实测 `grep -rn`）。紧凑视图**明确不持久化**——`app.js:4712` 原文："此项为即时生效的显示偏好，**不写入服务端配置，刷新后回到标准视图**"。

⇒ **不存在"既有 localStorage 命名约定可复用"**。本方案**新立约定**，并建议**顺带把紧凑视图也持久化**（同一 key 命名风格，避免"一个持久化一个不持久化"的割裂）。

| 项 | 约定 |
|---|---|
| key 前缀 | `jmc.`（即梦控制台缩写，全小写点分） |
| 主题 key | **`jmc.theme`** |
| 紧凑视图 key | **`jmc.compact`**（可选增强，值 `"1"`/`"0"`） |
| 值域 | `jmc.theme` ∈ {`"auto"`,`"light"`,`"dark"`}；非法值一律回落 `"auto"` |
| 读时机 | ① `<head>` 行内脚本（仅读 `jmc.theme`，写 `data-theme`，防 FOUC）；② `app.js` 初始化（读 `jmc.compact` → `applyDensity`） |
| 写时机 | `setTheme()` / `applyDensity()` 内，**改动即写**（即时生效偏好，与设置抽屉的「保存设置」解耦） |
| 容错 | `try/catch` 包裹（隐私模式下 `localStorage` 可能抛错）；读失败回落默认，写失败静默 |
| 与「保存设置」的关系 | **主题/紧凑不进服务端 `PUT /settings`**（它们是"本页外观偏好"，与生成参数无关；与现有 `compact` 的语义保持一致） |

## 五、风险清单

### 5.1 漏改导致深色局部破相（**最高风险**）

- **成因**：209 处字面量散落在 CSS + JS 内联 SVG + HTML 内联 style 三处；漏一处 = 深色下留一个浅色斑。
- **机械化自检（必须纳入 CI/验收命令）**：规定 **`:root` 与 `[data-theme]` 块之外，`app/styles.css` 不得再出现任何 hex/rgba**（`#fff` 之类也不许），并用 **去注释** 的 grep 校验：
  ```bash
  # 校验 styles.css：去注释、去 :root/[data-theme] 块后，不应再有颜色字面量
  node -e '
    const fs=require("fs");
    let s=fs.readFileSync("app/styles.css","utf8")
      .replace(/\/\*[\s\S]*?\*\//g,"")                 // 去注释
      .replace(/:root\{[\s\S]*?\n\}/,"")               // 去 :root 块
      .replace(/\[data-theme="dark"\]\{[\s\S]*?\n\}/g,""); // 去 dark 块
    const hits=(s.match(/#[0-9a-fA-F]{3,8}\b|rgba?\([^)]*\)/g)||[]);
    if(hits.length){console.error("✗ 残留字面量",hits);process.exit(1)}
    console.log("✓ styles.css 无残留字面量");
  '
  ```
  > ⚠ 必须**先去注释**：否则 `styles.css:12-14`（注释里的 `#7A7A7A/#67676B/#5E5E63`）与 `:923`（`#0B0D12`）会永远误报。
- **豁免白名单**（脚本里显式允许）：`api.js` 的 `GRADS` 6 组、§1.4.6 豁免清单里的"深色环境"颜色（`.codebox`/`.copywrap.on-dark`/`.fs-viewer`/`.toast`）。

### 5.2 深色下图片 / 视频 / 半透明层叠加的对比度

- 缩略图、`<video>` 产物、`.mask`/scrim 叠在深底上**边界消失**（§2.3）。
- **对策**：缩略图统一 `inset 0 0 0 1px var(--hairline)` 内描边（不占布局）；`.pv-video` 加边框；`.result-thumb.failed` 虚线用 `--err`。
- **验证**：深色截图逐一目视 + 计算 `.pv-video` 底(`#0B0D12`)与 surface(`#1C1C1E`)对比 = **1.09:1**（远低于 3:1）⇒ **必须加边框**。

### 5.3 阴影在深色下失效

- 浅色"靠阴影抬升"的模态/菜单/drawer，深色阴影几乎不可见。
- **对策**：深色把"抬升"语义交给 1px `--hairline` 边框；阴影只保留极弱纵深（§1.4.2）。
- **验证**：深色下打开设置抽屉/导入模态/菜单，确认有清晰边界。

### 5.4 切换主题与轮询 / 重渲染的竞态

- 主题只改 `<html>` 属性 + CSS 变量，**与 DOM 重绘正交**，`renderSettings()` / 列表轮询不会把主题切回去（§3.4）。
- **唯一需防**：JS 里若缓存了颜色值会失效——**现有代码未缓存颜色**，保持此约束即可。
- **次生风险**：`setTheme` 若被放进 `S.settings` 会触发 `settingsDirty`，被服务端旧值覆盖 ⇒ **严格禁止**（§3.4）。

### 5.5 已删全部 106 测试断言对验证强度的影响

- `0.17.1`（`9c4ec29`）删除了全部测试文件，含 **`server/ui-hidden-rules.test.js`**（`[hidden]` 静默失效防线）与 **`server/hl-rules.test.js`**（"每个 `ASSET_TABS` 取值都必须有 `.hl-*` 颜色规则"的静态断言，见 `styles.css:244` 的警告）。
- **影响**：深色新增 `.hl-*` / `.b-*` 覆盖规则时，**"漏一类素材着色"不会再有任何自动报警**，只会静默"某类型不着色"。
- **对策**：把这两条断言**以机械化校验的形式补回**（可写成 §5.1 的脚本扩展或独立 `node` 一行命令），纳入 A/B 两阶段验收；对照 `ASSET_TABS` 取值表逐一确认 6 个 `.hl-*`、5 个 `.b-*` 齐备。
