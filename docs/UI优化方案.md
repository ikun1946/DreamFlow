## 一、背景与目标

### 1.1 背景
当前控制台（v0.18.0）已具备完整的生成管理能力（分镜表、生成记录、素材库、设置），前端采用**令牌驱动**的设计体系（语义色 / 圆角 / 阴影 / 焦点环统一管理），组件层级清晰、空态/加载骨架/错误态齐全、响应式断点纪律严格。但在对 v0.18 前端三件套的实地核查中，确认**可访问性维度存在 WCAG AA 硬伤**，且中宽屏布局拥挤、组件一致性两项仍有提升空间。

> ⚠ 相对 v1.0 的重要认知修正：v1.0 把「深色模式」列为可低成本补齐的视觉增强，**属严重低估**（见 §3.1、§4.2）；v1.0 对「Esc 缺失」的诊断**方向性错误**（见 §3.3、§7）。

### 1.2 优化目标
| 维度 | 目标 |
|---|---|
| 可访问性（A11y） | 消除 WCAG AA 硬伤，对比度 ≥ 4.5:1；**把散乱的 Esc 实现收敛为统一机制**（一致性，非补缺） |
| 视觉设计 | 主色 hover/active 由 `opacity` 压暗改为语义色阶；**深色模式单列待办**（不并入本次主线） |
| 布局与响应式 | 消除 1280 笔记本横向滚动与顶栏拥挤；建立**文档化的 z-index 阶梯** |
| 组件一致性 | 统一禁用态（**6 处**取值）、清理死代码（**注意响应式那两条**）、ARIA 控件规范化 |

### 1.3 策略原则
按「**日常痛点 × 成本**」排序，而非按合规清单：
**M1 对比度+动效（改 2 处）→ M2 布局响应式 → M3 组件一致性 → M4 焦点/ARIA/Esc/A4 → W2 深色单列**。

## 三、现状问题诊断（六维度）

> 以下问题均经源码实测确认（grep / 行号定位 / 对比度实算），行号以 `89613c8` 为准。

### 3.1 视觉设计
- ✅ 单一强调色 Action Blue `#0066CC`、语义色克制、无装饰性渐变。
- ⚠ **无深色模式**，但**并非「成本低」**（实测）：`:root` 现有 **33 个令牌（其中 18 个为纯颜色令牌）**；全 `styles.css` 有 **114 处 hex 字面量 + 35 处 rgba 字面量 = 149 处非令牌颜色**（`#fff` 占 **42 处**，如 `.badge.draft{background:#fff}`、`.rec-head .input-sm{background:#fff}`:1015）；且焦点令牌 `--focus:0 0 0 2px #fff,0 0 0 4px var(--primary)`（`:27`）**值本身含 `#fff`** —— 深色下焦点环会发光。**只覆盖令牌，这 149 处不翻转** ⇒ 见 §4.2。

## 四、详细实施步骤

### 4.1 W1 · 可访问性硬伤修复（P0）

**目标对象**：`app/styles.css` 令牌与动画定义、`app/app.js` 模态/弹窗交互层。

1. **备份**：`app/styles.css`、`app/app.js` → `backup/ui-a11y-YYYYMMDD/`。
2. **A1 对比度**：`--ink48`（`styles.css:12`）改为 `#5E5E63`（**实算 6.45:1**）；若不想加重灰字视觉重量，可用折中值 **`#67676B`（≈5.6:1）**。关键次级文字（列头 `:172` / 状态）可升至 `--ink80`。
   ```css
   /* styles.css:12 —— 二选一，不要同时用 */
   --ink48:#5E5E63;   /* 实算 6.45:1，强 AA/AAA 余量 */
   /* --ink48:#67676B; 折中 ≈5.6:1，灰感更轻 */
   ```
3. **A2 reduced-motion**：`styles.css` 末尾追加全局块（保留 transform 显隐逻辑）：
   ```css
   @media (prefers-reduced-motion:reduce){
     *,*::before,*::after{ animation-duration:.001ms!important; transition-duration:.001ms!important; }
   }
   ```
4. **A3/A6 焦点陷阱**：`app.js` 实现 `trapFocus(dialog)` —— 打开时聚焦首个可聚焦元素、拦截 Tab 循环、关闭后焦点归位到触发按钮。作用于全部 `role="dialog"` 容器 + 设置抽屉。
5. **A4 触摸目标（重设计，替代原「padding 扩热区」）**：原写法有两处硬伤 ——① `styles.css:58–62` 明确警告这批按钮**必须 `padding:0`**（否则图标不居中，实测偏移 +2~+6px），`padding` 扩容会破坏布局；② `.thumb` 仅 **40×52**（`--thumb-w:40px/--thumb-h:52px` `:33`），把热区扩到 28–32px 会盖住缩略图大部分，「视觉尺寸不变」**几何上做不到**。**分控件方案如下**：

| 控件 | 现值/位置 | 不可达？ | 方案 | 尺寸上限理由 |
|---|---|---|---|---|
| `.cbx` | 16×16（`:206`） | 否 | `position:relative` + **`::before`** 伪元素 `inset:-6px` 外扩热区至 28×28（**勿用 `padding`**；`::after` 已被 `.cbx.partial` `:217` 占用，故用 `::before`） | 序号列宽 44px，28 内不越界 |
| `.icon-act` | 18×18（`:383`） | 否 | `::before` 外扩至 ~28px | 与相邻图标间距有限，封顶 ~30px 防重叠 |
| `.zoom-btn` | 22×22（`:252`） | 否 | `::after` 外扩至 ~32px（**它不在 `:63-69` 的 `padding:0` 列表内，一并按同法处理，不要用 padding**） | 位于标题行右端，向右/下扩不压正文 |
| `.thumb .rm` | 14×14，`top:2px right:2px`，`display:none`→`:hover` 才 `grid`（`:299-303`） | **是（触屏不可达）** | ①**可达性优先**：`@media (hover:none){ .thumb .rm{display:grid} }` 令触屏常显；②视觉尺寸封顶 **20px**（缩略图仅 40 宽，24px 已占 60%）；③根治：把「删除」提升为**卡片/行级**入口，不再依赖缩略图内小钮 | 「不可达」比「太小」严重——先修可达性，再谈尺寸 |

6. **A5 ARIA**：图标按钮补 `aria-label`；`switch` 补 `role="switch"`+`aria-checked`+方向键；`stepper` 补 `role="spinbutton"`。
7. **Esc 统一（重构，非补缺）**：抽公共 **`bindEsc(dialog, onClose, {capture, stop})`**，把上表 **16 处**各自为政的监听器收敛到一处：**统一在 `close()` 内 `removeEventListener`**（根治 §3.3-③ 的残留泄漏）、统一相位、明确 `stopPropagation` 策略；`bindStatic` 里那条「无条件 `closeDetail()`」改为「仅当详情打开时关闭」。

### 4.2 W2 · 视觉设计增强 —— **独立待办 · 不在本次主线**

> 原文说「令牌已是 CSS 变量，补 `[data-theme="dark"]` 成本低」**低估**。实测前提不足：

- `:root` 仅 **33 个令牌（18 颜色）**，但散落 **149 处非令牌颜色**（114 hex + 35 rgba，#fff 42 处）——覆盖令牌**不会翻转**它们。
- 焦点令牌 `--focus`（`:27`）**值内含 `#fff`**，深色下会发光。

**前置条件（必须先做）**：
1. 一轮「**颜色字面量令牌化**」：把 149 处颜色收敛为语义令牌（至少：表面/边框/次级字/白底等），并让 `--focus` 引用令牌而非硬编码 `#fff`；
2. 回归验证颜色令牌化未改变明色渲染（依赖 §7 的截图硬门禁）。

**完成后**再补 `[data-theme="dark"]` 覆盖 + 引入 `--primary-600:#0058B0`、`--primary-700:#004C99` 替代 `opacity` 压暗（`.btn-primary:hover` `:156`）+ `app.js` 主题切换与 `localStorage` 持久化。

### 7.2 验证方法

> ⚠ **重要前提**：项目在 **0.17.1（`9c4ec29`）已按用户要求删除全部 10 个自动化测试文件**（`artifact-history`/`audio-budget`/`hl-rules`/`migration`/`model-limits`/`paths-layout`/`project-isolation`/`task-state`/`ui-hidden-rules`/`worker-guard`）。被删的 **`ui-hidden-rules`** 与 **`hl-rules`** 正是「**不报错、只静默失效**」类缺陷的防线。**因此回归现在只能靠手工验收**，验证强度必须相应提高。

- 🔒 **硬门禁（唯一自动防线）**：`agent-browser` 在 **1440 / 1280 / 1024 / 860 / 640 / 420** 六档截图，确认 **0 个 JS 控制台错误**；任一档报错即**不得提交**。工作区 `_ui-check/` 有 **20 张历史 PNG** 可作对比基线。
- **静默失效手工清单**（替代已删的 `ui-hidden-rules`/`hl-rules`）：① 逐一确认 `[hidden]` 切换（视图/弹层）均真正隐藏；② 逐一确认 **6 种素材类型**（`character/scene/prop/audio/firstFrame/storyboard`）着色都不为无色（`styles.css:241-246`）。
- **触屏专项**：`hover:none` 下确认 `.thumb .rm` 可见可点（A4）。
- **可访问性**：axe-core / Lighthouse a11y 跑分（**辅助**）；键盘 Tab 全链路走查；WebAIM 对比度复核。
- **构建幂等**：每次 `node build.js` 后核对 `dist/` 字节数与改动前一致。
- **运行时隔离**：旧服务旧代码保持运行；本方案为纯前端静态改动，不影响后端逻辑，亦不触发 v2→v3 数据迁移。

### 7.3 回退方案
每个里程碑前均执行 `backup/<feature>-YYYYMMDD/` 全量备份；如验证不通过，直接还原 `app/` **四文件**即可，无需触及 `server/` 与 `db.json`。
