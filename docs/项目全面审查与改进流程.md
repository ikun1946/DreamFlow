## 2. 值得保留的资产（改之前先认清哪些不能碰坏）

这些是项目真正的护城河，任何重构都必须把它们当**不可回退的契约**：

1. **零运行时依赖**：后端只用 Node 内置模块，前端原生 HTML/CSS/JS。它换来的是"装机不需要 npm install 成功"这一条极硬的可靠性。
2. **持久化的三重保险**：原子写（临时文件 + fsync + rename）、轮转备份、损坏隔离与恢复链；并且**明确拒绝在库未加载时写盘**（防止空值覆盖真实数据，这条是事故后加的硬拦）。
3. **路径安全的单一出口**：`paths.js` 是"磁盘布局 + URL 形状"的唯一事实来源，`contained()` 用 `base + path.sep` 比较（注释里写明了 `output` 与 `output-bak` 的教训）。
4. **自更新的四条硬约束**：只接受 https（local 模式除外）、下载后必须校验 sha512、安装器必须 `/S --updated --force-run`、令牌只进不出。外加 `safeArtifactName()` 白名单，堵住了 `../` 路径穿越。
5. **幂等键含作用域**：`withIdempotency` 的键 = 路径 + projectId + workspaceId + 客户端键，修掉了"同一把 key 打到另一个项目会回放第一个项目响应"的跨项目串线。
6. **数据隔离与删除保护**：项目级磁盘分区（`projects/<id>/assets|output`）、软删/彻底删除分离、彻底删除前有只读预览（统计分镜/素材/文件数）与归档。
7. **文档纪律**：`AGENTS.md` 短契约 + 事故注释 + DoD 收尾清单 + `docs/项目文档.md` 完整说明书。这种"把踩过的坑写成注释"的密度在个人项目里非常少见，是后续维护的最大杠杆。
8. **桌面链路的关键判断**：自更新不引 `electron-updater` 而直接用 electron-builder NSIS 的三个开关，并用 `spawn`/`error`/超时三态收敛 Promise（修掉了"同 tick resolve 把启动失败报成成功"的真实竞态）。

### P1-1　`server.js` 静态路由的前缀校验与 `paths.contained()` 语义不一致（同类漏洞只修了一半）

**证据**

```js
// server/server.js:210-218  —— 仍在用裸 startsWith
if (pathname.startsWith('/app/')) {
  const p = path.normalize(path.join(PROJECT_ROOT, pathname));
  if (!p.startsWith(path.join(PROJECT_ROOT, 'app'))) { res.writeHead(403); return res.end(); }
  ...
}
if (pathname.startsWith('/dist/')) {
  const p = path.normalize(path.join(PROJECT_ROOT, pathname));
  if (!p.startsWith(path.join(PROJECT_ROOT, 'dist'))) { res.writeHead(403); return res.end(); }
  ...
}
```

```js
// server/paths.js:168 —— 同一仓库里已经写对了
/* ⚠ 必须比较 `base + sep` 前缀，不能只 startsWith(base) ——
   否则 base 是 `.../output` 时，兄弟目录 `.../output-bak` 会被误判为在范围内。 */
function contained(base, target) {
  const b = path.resolve(base);
  const t = path.resolve(target);
  if (t === b) return null;
  return t.startsWith(b + path.sep) ? t : null;
}
```

**影响**

- 当前仓库里不存在 `app-*` / `dist-*` 兄弟目录，因此**暂时不可直接利用**；但这是**潜伏**问题：一旦有人新增 `app-old/`（备份旧版前端）、`dist-backup/`、`app.old/` 之类目录，`/app/..%2fapp-old/xxx` 这类请求就会绕过判断，把仓库内其它文件当作静态资源返回。

### P1-2　CSP 仍允许 `'unsafe-inline'`，而前端有 63 处 `innerHTML`

**影响**

- 当前威胁模型是"本地单机、内容来自用户自己"，风险有限；但一旦出现"用户粘贴的提示词 / 素材文件名 / 导入的旧数据"被渲染进 `innerHTML` 而漏了 `esc()`，就是本地存储型 XSS（可读写本地 API、可触发真实生成消费积分）。

   - 在响应头 `Content-Security-Policy` 里带同一个 nonce；
   - 覆盖 `app/index.html` 的"主题防闪"内联脚本与注入的 `window.APP_CONFIG` 脚本。
2. **第二步（结构治理）**：把 `app.js` 里的内联 `style="..."` 收敛为 CSS class 或 CSS 自定义属性（`el.style.setProperty('--x', v)` 不算内联 style 属性，不受 CSP 限制），之后 `style-src` 也可去 `'unsafe-inline'`。
3. **配套纪律**：加一条轻量自检（写进 `scripts/check-project.js` 或新 `scripts/lint.js`）——`innerHTML` 模板里出现 `${...}` 插值且该表达式未包 `esc(` 时给出告警清单（允许白名单）。

**验收标准**

- 响应头里 `script-src` 不含 `'unsafe-inline'`；页面无 CSP 报错；`npm run smoke:web`、`npm run e2e`、桌面 smoke 全绿。
- `innerHTML` 未转义插值的告警清单为空（或全部在白名单中并有注释说明）。

### P2-1　持久化写放大：每次保存都全量序列化整个库

**验收标准**

### P2-5　可访问性与键盘可达性不足

**证据**（`app/index.html` / `app/app.js` 实测计数）

| 指标 | 数量 |
| --- | --- |
| `aria-*` | index.html 9 处、app.js 10 处 |
| `role=` | index.html 5 处、app.js 2 处 |
| `<label>` | 2 处 |
| `tabindex` | **0 处** |

抽屉（`#settingsDrawer` 有 `aria-hidden`）、导入弹层、详情弹层均无 `tabindex` / focus trap / Esc 关闭的统一实现（需人工确认）。

**影响**

- 键盘用户与读屏用户无法完整走完"导入 → 提交 → 打开设置 → 关闭"的主流程。

**修复动作**

1. 抽象一个 `openModal(el)` / `closeModal()`：进入时记住焦点并聚焦首个可聚焦元素，离开时归还焦点；`Esc` 关闭；`Tab` 在弹层内循环。

3. 给表格补 `role="table"/"row"/"columnheader"` 或改用语义化标签；给批量操作结果加 `aria-live="polite"` 播报。
4. 键盘走查清单写进 `docs/项目文档.md`（前端实现要点一节）。

**验收标准**

- 仅用键盘可完成主流程，焦点不会跑到弹层外。
- 弹层有 `role="dialog"` 与可读名称；图标按钮均有 `aria-label`。
- 至少一次键盘走查结果记录在文档中。

### P2-6　临时产物与本地残留缺少治理

**证据**

- 仓库根存在 `.test-tmp/`（测试沙箱目录，已 gitignore，但会残留）；

**影响**

- 长期开发后根目录会积累临时目录，容易被误打包或误提交。

3. 复核 `dist/` 与 `app/` 的"新旧"判定：改为**内容哈希**或"构建产物内是否包含 app.js 的指纹"，避免依赖 mtime（mtime 在 clone / CI 上不可靠）。

**验收标准**

- `npm test` 结束后 `.test-tmp/` 为空或不存在。
- `npm run check` 的"产物同步"判定不依赖 mtime（代码层面可见），且在 CI 上稳定通过。

### 7.2 不可回退的红线（摘自 `AGENTS.md`，改造期间必须持续遵守）

1. 不提交 `server/data/`（用户素材与视频）与 `release/`（上百 MB 二进制）。
2. 不删 `build/icon-source.png` / `icon.png` / `icon.ico`（源图删了再也生成不出图标）。
3. 不删用户的 `db.json` 与 `projects/`（不可恢复）。
4. 不在应用里嵌 GitHub 令牌（令牌只进不出）。
5. 自更新只接受 https（local 模式除外）；下载后必须校验 sha512；安装器必须 `/S --updated --force-run`。
6. 改完 `app/` 必须 `node build.js`；"语法通过"不等于"能用"。
