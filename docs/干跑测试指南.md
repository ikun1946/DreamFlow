# 干跑测试指南

> 状态：现行
> 权威范围：干跑（不消耗积分地核对提交命令）的三种方式与页面操作步骤
> 最新流程见：`docs/项目全面审查与改进流程.md`

> 状态：现行
> 权威范围：干跑（不消耗积分地核对提交命令）的三种方式与页面操作步骤
> 最新流程见：`docs/项目全面审查与改进流程.md`

> 目标：**在页面上点一次「提交」，但不把它发送给即梦**，然后在这个页面上直接读到「这次提交实际会执行的命令」。
>
> 结论：用页面右下角素材面板顶部的 **「干跑提交」** 按钮。它与正式提交走**完全相同**的链路（同一个接口、同一个 worker、同一个命令组装出口），只在最后一刻不 spawn 子进程。因此页面显示的这条命令 **== 正式提交时会执行的命令**（逐字一致，唯 `--submit-id` 例外，见注意点 ③）。

---

## 一、三种测试方式，先选对

| 方式 | 入口 | 会改状态吗 | 能看到什么 | 适用 |
|---|---|---|---|---|
| **① 干跑提交**（推荐） | 页面 **「干跑提交」** 按钮 | **否**（提交后回到「未提交」） | 走完整链路的**真实命令** + 路由/模式/引用/适配 + 可选 CLI 本地校验 | **你问的这种测试**：验证「提交后到底发什么命令」 |
| ② 只读预览 | `POST /storyboards/{id}/dry-run` | 否 | 与①同样的命令与校验结果，但不经过队列/worker | 单条排障、反复试参数（面板「用 CLI 本地校验」按钮走的就是它） |
| ③ 服务级干跑 | 启动时 `JC_DRY_RUN=1` | 否 | 同①，但**所有**提交都干跑 | 整服务联调；**用完必须去掉**，否则正式提交也不会派发 |

## 二、页面操作步骤（方式①）

1. 启动服务（**不要**带 `JC_DRY_RUN`）：`node server/index.js`，浏览器打开 `http://127.0.0.1:8787/`。
2. 在表格里**勾选**要试的分镜（可多选，一次提交多条会一起列出来）。
3. 点右侧素材面板顶部的 **「干跑提交」**（在「提交所选」右边）。
4. 等待 1–3 秒（worker 1.5s 一拍），**「干跑命令核对」弹层自动打开**，逐条列出命令。

弹层里可做的事：

- 每条命令 **「复制命令」**，或右上 **「复制全部命令」**（带 `# 分镜 N` 注释，便于贴进排查记录）；
- **「用 CLI 本地校验」**：⚠ 2026-09-18 画布 CLI 移除后此能力已下线 —— 它依赖画布 CLI 专属的 `--dry-run`；创作 CLI 没有该 flag，命令由后端按 `server/models.js` 能力表组装并本地校验，页面上的命令即实际执行的命令。
- 分镜的状态下次刷新会回到「未提交」——**这是对的**，干跑不占状态。

命令行（不想点页面时）：

```bash
curl -X POST http://127.0.0.1:8787/api/v1/storyboards/batch-submit \
  -H "Content-Type: application/json" \
  -d '{"ids":["st_xxxx"],"dryRun":true}'
# 然后读单条详情，命令在 data.dryRunPlan 里
curl http://127.0.0.1:8787/api/v1/storyboards/st_xxxx
```

## 三、页面能读到什么（面板字段）

| 字段 | 含义 |
|---|---|
| 命令（`$ …`） | **唯一要看的东西**：后端交给 CLI 的完整命令行，等于把 argv 用空格拼起来 |
| argv 逐项 | 同上，数组形式、逐项编号；排查「引号/空格/编码」问题时看这个，比命令行可靠 |
| 执行引擎 / 模式 | 恒为 `创作 CLI`（画布 CLI 已移除）；模式 `t2v`（无视觉引用）/ `m2v`（有图或音频引用） |
| 模型 | 实际传给 CLI 的模型名（创作域名；历史画布域名会在提交前被自动迁移为创作等价名） |
| 时长 / 画幅 / 分辨率 | 分镜参数；**注意分辨率大小写会被按模型规格归一**（happyhorse/wan 是 `720P`，seedance 是 `720p`） |
| 参数适配 | 被自动改过的参数（如「分辨率 1080p → 720p」），这类改动不会静默发生，都会列出来 |
| 未匹配 flag | 模型规格里找不到对应参数名的参数，已跳过 —— 出现这项说明**参数没传进去**，要留意 |
| 素材引用 | `角色 → node:xxx` 形式；为空表示命令里不含 `--ref`（见注意点 ⑦） |
| 幂等键 | `--submit-id`，干跑显示的是**预览值**，正式提交会重新生成 |
| 干跑时间 / 来源 | 时间戳为 **UTC**；来源区分「本次干跑提交」与「服务端干跑模式」 |

## 四、查看命令时需要注意的关键点

### 必须知道的

**① 命令不是前端生成的 —— 前端发的请求里没有命令。**
前端发出的只是 `POST /api/v1/storyboards/batch-submit`，体仅 `{"ids":[…],"dryRun":true}`。命令由**后端**根据分镜参数 + 实时模型目录组装。所以「核对前端发出的命令」准确说是：核对**这次提交最终会执行什么命令**。请求体里那点内容在上面第一个 codebox 之外的接口层面，页面上看不到（也不需要看）。

**② 「不发送给即梦」≠ 完全不联网。**
干跑不做的：不 spawn `--run` 子进程、**不创建生成任务、不报价、不扣积分**。
干跑仍会做的：提交前的 CLI 可用性探测，以及为组装命令而拉取的**实时模型目录**（模型名 / 分辨率 / 画幅枚举）。这是为了命令里的 `--model`、`--resolution` 等值正确。若 CLI 完全不可用，干跑也会被拒（提交接口返回「即梦 CLI 未连接，无法提交」）。

**③ `--submit-id` 必然不同，这不是错误。**
它是幂等键，正式提交时**先生成并落盘再 spawn**（重试复用同一个）。干跑时只生成一个**预览值、不落盘**，所以干跑看到的 uuid 与随后正式提交的 uuid 不会相同，其余部分应逐字一致。

**④ 分镜详情里那行命令，和干跑记录是两回事。**
没有干跑记录时，详情里展示的是**按路由推演的示意命令**，带 `<uuid>` 之类占位符，不是真实可执行的。**只有带「干跑记录」注释的那条才是真命令。**

**⑤ 干跑记录只保留最后一条。**
`dryRunPlan` 会被下一次干跑覆盖。要一次核对多条，就**多选后一次提交**，面板会全部列出来并支持「复制全部」。

**⑥ 时间戳是 UTC。**
`at` 形如 `2026-09-18T07:37:16.448Z`，比北京时间早 8 小时。别因为「时间对不上」以为记录是旧的。

### 容易误判的

**⑦ 命令里没有 `--ref`，不等于素材没绑上。**
参考图通过创作 CLI 的 `--image` / `--audio` 直接引用本地文件（原画布 `--ref node:<id>` 引用方式已随画布 CLI 移除）。看「素材引用」这一栏，并以「执行引擎」为准。

**⑧ 状态回到「未提交」是正常现象。**
干跑结束后任务状态回 `draft`，进度归零，看起来像"没提交成功"。判据是**分镜详情里出现了干跑记录与【干跑】日志**，而不是状态。

**⑨ 命令正确 ≠ 生成成功。**
`--dry-run` 能覆盖的只是本地参数与语义（`sideEffects: []`），它明确列出 8 项 `unverified`：鉴权、项目访问、草稿真状态、模型规格、报价、余额、派发与生成等。**这些只有真跑才知道。**

**⑩ 忘了关服务级干跑，会静默"提交成功但不生成"。**
用 `JC_DRY_RUN=1` 启动过服务，之后所有提交（含「提交所选」）都只组装命令、不派发。页面底部状态栏会显示 **「干跑模式」** 徽标作为提醒；弹层里也会有红色警示条。恢复真实执行需**重启服务且不带该变量**。

### 危险动作

**⑪ 不要把复制出来的命令直接粘进终端执行。**
命令里带 `--run`（报价 → 批准 → 运行 → 等终态），直接跑会**真的提交并扣积分**。只想再验一次，就在末尾追加 `--dry-run`：

```bash
dreamina multimodal2video --prompt … --duration 5 --ratio 16:9 --video_resolution 720p --model_version seedance2.0fast …
```

**⑫ 干跑可以放心反复做。**
不扣分、不建任务、不改任务状态；唯一的副作用是分镜上留一条最后的干跑记录与几行日志。想清空这条记录，正式提交一次或删掉该分镜即可。

## 五、命令结构速读（画布 CLI 示例）

```bash
dreamina-canvas                              # CLI 可执行文件（配置项 cliPath）
  --format json --non-interactive --region cn # 全局开关：机器可读输出 / 不交互 / 区域
  node create video                          # 子命令：在画布上新建一个视频节点
  --run --wait                               # 报价→批准→运行→等待终态（干跑不执行这一段）
  --submit-id <uuid>                         # 幂等键：重试复用同一个，避免重复扣费
  --mode t2v                                 # 生成模式：t2v / m2v / first_last_frame（必填）
  --credit-ceiling 200                       # 积分安全阀：报价超上限即停在运行前、不扣费
  --prompt "…"                               # 提示词（含空格/引号，看 argv 更可靠）
  --model seedance_2.0_vip                   # 模型名（画布归属映射后的实际值）
  --duration 5 --ratio 16:9 --resolution 720p
```

创作 CLI 路径的命令形态不同（`text2video` / `multimodal2video`，用 `--model_version --video_resolution` 等参数名），且**没有 `--dry-run`**，所以它的「CLI 本地校验」一栏会显示「无本地校验能力」。
