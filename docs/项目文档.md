## 1. 项目概述

**即梦批量生成控制台**是一个面向 AI 短剧 / 分镜视频生产流程的**前端工作台**：把一个批次的多个分镜提示词集中管理，支持批量导入、素材绑定（角色 / 场景 / 道具 / 首帧图 / 分镜图）、时长控制、批量提交生成、进度轮询与结果预览。

核心特征：

- **前后端一体的真实链路**：前端零依赖原生 HTML / CSS / JavaScript；后端（`server/`，零 npm 依赖）承载接口并通过即梦 CLI 完成真实生成。**无任何演示/模拟数据**——空库启动，数据一律来自导入 / 接口创建。
- **前后端契约先行**：`docs/前端页面与接口对接说明.md` 定义了接口契约；前端在 `app/api.js` 内统一走真实 HTTP，`baseUrl` 自动适配同源托管与 `file://` 双击两种打开方式。
- **单页应用，三个面板一个组件**：P1 主界面（分镜表）、P2 批量导入弹窗、P3 设置抽屉，外加嵌在表格行内的 C1 时长控件。
- **产物双轨**：`app/` 开发版（四文件分层）+ `dist/` 发布版（单文件内联，由 `build.js` 生成）。

## 2. 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 页面 | 原生 HTML5 | 单页，`lang="zh-CN"`，无路由 |
| 样式 | 原生 CSS | 明色视觉系统，设计令牌集中在 `styles.css` 的 `:root`（强调色 Action Blue `#0066CC`） |
| 逻辑 | 原生 JavaScript（ES2017+） | IIFE 模块，无打包器；`api.js` 挂 `window.Api`，`app.js` 只消费 `Api` |
| 请求 | `fetch` | 统一响应信封 `{ code, message, data, traceId }`，`code !== 0` 视为业务失败 |
| 构建 | Node.js + `fs`/`path`（`build.js`） | 仅做文本内联，无依赖安装 |
| 后端 | Node.js 内置模块（`server/`，零 npm 依赖） | 22 个契约接口 + 即梦 CLI 适配层（唯一真实链路），见 `docs/后端服务设计方案.md` |
| 运维脚本 | Bash + `curl` + `git`（`scripts/push-to-github.sh`） | 一次性建仓推送，不参与应用运行 |

## 3. 整体架构

```
┌────────────────────────── 浏览器（单页应用） ──────────────────────────┐
│  index.html（骨架）                                                   │
│  ┌────────────┐   消费 Api 对象    ┌───────────────────────────────┐  │
│  │  app.js    │ ─────────────────→ │  api.js（接口层，唯一后端耦合） │  │
│  │ 状态/渲染/  │                    │  全部请求走真实 HTTP fetch，    │  │
│  │ 交互/轮询   │ ←───────────────── │  数据一律来自后端，无本地模拟    │  │
│  └────────────┘   数据 / ApiError   └──────────────┬────────────────┘  │
└───────────────────────────────────────────────────┼───────────────────┘
                                                    ▼
                              真实后端 /api/v1（契约见 docs/前端页面与接口对接说明.md；
                              后端设计方案见 docs/后端服务设计方案.md）
```

分层铁律（写在两个文件头部的约定）：

- **`api.js` 不碰 DOM**：只负责「请求 → 数据 / `ApiError`」。
- **`app.js` 不拼 URL**：只负责「数据 → DOM」与用户操作，一律通过 `Api.xxx()` 调用。

## 5. 模块划分

### 5.1 app/api.js —— 接口层

| 子模块 | 职责 |
|---|---|
| `CFG` | 读取 `window.APP_CONFIG`：`baseUrl`（同源自动取 `/api/v1`，file:// 取本机后端绝对地址）、`token`、`projectId` |
| `ERR` / `ApiError` | 业务错误码表（0 / 40001 / 40100 / 40300 / 40400 / 40900 / 42900 / 50000 / 51001–51005）与统一错误对象 |
| `META` | 默认枚举兜底（非演示数据）：仅用于 `GET /meta/options` 返回前的骨架渲染，运行时选项以后端下发为准 |
| `grad()` | 缩略图兜底渐变（后端未提供图片资源时保持可读性） |
| `httpRoute()` | 真实请求：拼 URL + query、带 `Authorization: Bearer` 与 `Idempotency-Key` 头、解信封、`code !== 0` 抛 `ApiError` |
| 对外 `Api` 对象 | 22 个方法（`getOptions` / `listStoryboards` / `batchSubmit` / `importPreview` 等），供 `app.js` 消费 |

### 5.2 app/app.js —— 状态与交互层（975 行）

| 子模块 | 职责 |
|---|---|
| 全局状态 `S` | 列表、统计、枚举、适配器、设置、勾选集合、筛选、素材面板状态、轮询器、导入状态 |
| 渲染 | `renderTopbar` / `renderColhead` / `renderTable`（骨架屏 / 空态 / 错误态 / 数据四态）/ `renderPanel` / `renderStatusbar`；轮询时走 `renderRowsOnly` 局部重绘避免 hover 抖动 |
| 轮询器 | 全局单例；仅对 `generating`/`queued` 行轮询；基线 3s，连续 3 次无变化退避 6s → 10s 封顶；异常指数退避封顶 30s；`visibilitychange` 隐藏暂停、恢复立即拉一次；全部终态停止；有变化时整行局部更新，出现终态则重拉列表校准统计 |
| C1 时长控件 | 步进器（乐观更新 + **300ms 合并提交** + 失败回滚）、双击直接输入（Enter 提交 / Esc 取消 / 失焦提交）、单击预设下拉（5/10/12s + 自定义）、已完成行锁定 |
| 行操作 | 上移 / 下移（`reorder`）、取消（`cancel`）、重试（`retry`）、详情弹层（`getStoryboard`，回显 `cliCommand` 与 `logs`）、删除（`batchDelete` 带 `force`） |
| 批量操作 | 提交所选（`batchSubmit`，受理项乐观置 `queued`）、批量改时长（`batchDuration`，逐条 `skipped[]` 提示）、批量删除 |
| 素材面板 | 角色 / 场景 / 道具三个 Tab、搜索防抖 250ms、绑定（点表格「＋」槽后点素材卡）/ 解绑（悬停「×」）；同一 role 单值槽位覆盖、角色可多个 |
| P2 导入弹窗 | 粘贴防抖 400ms 调 `importPreview`、分隔符 chips（换行 / `;;` / `\|` / `---` / 自定义）、预览重复 / 超长标注、确认调 `importConfirm`，新行自动勾选 |
| P3 设置抽屉 | 分隔符（与 P2 同源）、默认模型 / 画幅 / 分辨率 / 时长（点击循环切换）、并发步进、失败自动重试开关、Mock / CLI 模式切换 + CLI 可用性状态卡、保存 `putSettings`、恢复默认 `resetSettings` |

### 5.3 build.js —— 构建脚本（107 行)

把 `app/` 四文件按锚点内联为 `dist/即梦批量生成控制台.html`。内置四道校验：

1. 源码中不得有字面量 `</script`（防止内联截断脚本块）；
2. `index.html` 必须存在样式锚点与脚本锚点（两行相邻、`\n` 分隔）；
3. `String.replace` 必须用**回调函数**形式（字符串形式会把 `$$` / `$&` 当替换占位符吞掉，产物静默损坏——实际踩过的坑）；
4. 产物后置校验：`$$` 数量一致、`<script>` 块恰 2 个、`<style>` 块恰 1 个、无残留外部引用。

### 5.4 scripts/push-to-github.sh —— 运维脚本（130 行）

一次性建仓推送：校验 `GITHUB_TOKEN` → 读取账号 → 创建 **private** 仓库 → 临时带令牌 URL 推送 → 立即重置远端 URL（`EXIT` trap 兜底，令牌不落 `.git/config`）→ 三重私密性验证（API 回查 `private:true`、未登录访问 404、协作者为空）。只用 `git` + `curl`，不依赖 `jq`。

## 6. 核心功能描述

### 6.1 P1 主界面 · 分镜表

- **表格 10 列**：序号 / 分镜·提示词（含时长控件与参数行）/ 角色 / 场景 / 道具 / 首帧图 / 分镜图 / 结果与进度 / 状态 / 操作。列宽由 `COLUMNS` 配置驱动，列头由 JS 生成。
- **素材槽位规则**：角色列可多个（最多展示 2 + 「＋」），场景 / 道具 / 首帧图 / 分镜图各 1 个；单值槽位有值时「＋」消失；缩略图为由 ID 派生的稳定渐变（离线可跑，不依赖外部图片）。
- **状态机**：`queued（排队中）→ generating（生成中）→ succeeded（已完成）/ failed（失败）`，另有 `canceled（已取消）`。`status` 只由后端下发，前端不做状态推断。
- **勾选与批量**：勾选后底部状态栏出现「批量改时长 / 删除所选 / 取消选择」，素材面板出现「提交所选 N」。
- **紧凑视图**：顶栏一键切换行高 210px ↔ 132px（CSS 变量整体缩放缩略图尺寸）。
- **详情弹层**：完整参数、远端 ID、重试次数、失败原因、**将要执行的 CLI 命令**回显、执行日志。
- **产物预览**：点击已完成行的结果缩略图，弹层展示封面渐变 + 视频地址（`videoUrl`）。

### 6.2 P2 批量导入提示词

- 粘贴多段文本 → 防抖 400ms 自动调预览接口 → 按 `;;` / `|` / `---` / 换行 / 自定义分隔符拆分 → 实时显示「已识别 N 段，将创建 N 个分镜」+ 逐段预览（重复 / 超长标注）。
- 拆分规则与后端必须一致：**不裁剪段内空格、只 trim 首尾、丢弃空段**（`splitSegments()`）。
- 确认导入：带 `Idempotency-Key` 防重放；新行插入表格并自动勾选，可直接批量提交。

### 6.3 P3 设置抽屉

- 四个分组：提示词分隔符（与 P2 同源数据，此处保存为持久默认）、生成参数默认值、队列与执行（并发 1–5、失败自动重试最多 2 次）、接口对接（Mock / CLI 模式切换）。
- CLI 未就绪时显示琥珀色状态卡「任务将入队但不执行」；`batch-submit` 在 CLI 模式且不可用时直接返回 `51001` 拒绝。
- 保存走 `PUT /settings` 全量提交（`40001` 返回 `data.fields[]` 行内校验信息）；恢复默认支持按 scope（delimiter / defaults / queue）部分重置。

### 6.4 进度轮询（前端最重要的机制）

| 项 | 实现 |
|---|---|
| 触发条件 | 列表中存在 `generating` / `queued` 行 |
| 接口 | `GET /storyboards/progress?ids=...`（单次上限 50 个 ID，前端切片） |
| 增量语义 | 后端**只返回有变化的项**，无变化返回 `[]` |
| 退避 | 基线 3s；连续 3 次无变化 → 6s → 10s 封顶；异常指数退避封顶 30s（`42900` 不弹错） |
| 暂停 / 恢复 | 页面隐藏暂停；恢复可见立即拉一次 |
| 停止 | 全部活跃任务进入终态 |
| 收口 | 任一行到达终态时重拉列表，以服务端统计为准 |
| 视觉 | 进度条 350ms 线性过渡（CSS），服务端跳变不闪烁 |

### 6.5 乐观更新策略

- **改时长**：立即生效 → 300ms 防抖合并为一次 `PATCH` → 失败回滚原值 + Toast（`40900` 已完成锁定）。
- **批量提交**：`accepted[]` 项立即置 `queued` 并启动轮询；`rejected[]` 项行内红条展示原因。
- **删除 / 重排**：不做乐观更新，服务端确认后生效。

## 7. 数据模型（与契约文档 3.x 一致）

- **Storyboard（分镜）**：`id(st_)`、`projectId`、`batchId`、`seq`、`prompt(1–2000 字)`、`negativePrompt`、`durationSec`、`model`、`ratio`、`resolution`、`seed`、`motion(0.00–1.00)`、`status`、`progress(0–100)`、`etaSeconds`、`remoteId(jm_)`、`videoUrl`、`coverUrl`、`currentFrameUrl`、`elapsedMs`、`retryCount`、`errorCode/errorMessage`、`assets[]`、`createdAt/startedAt/finishedAt`、`canEditDuration`（服务端裁决）。
- **Asset（素材）**：`id(as_)`、`projectId`、`name`、`type(character/scene/prop)`、`url`、`thumbUrl`、`width/height`、`tags[]`、`inCurrentShot`。
- **AssetRef（绑定）**：`assetId` + `role(character/scene/prop/firstFrame/storyboard/output)` + 展示字段。
- **Settings**：`delimiter{type,value}`、`defaults{model,ratio,resolution,durationSec,motion,negativePrompt}`、`queue{concurrency,autoRetry,maxRetry}`、`adapter{mode,cliAvailable,cliVersion}`（`cliAvailable` 只读，由后端探测下发）。

## 8. 错误处理与文案

统一信封 `{ code, message, data, traceId }`；`app.js` 的 `ERR_TEXT` 提供兜底文案表（`51001` CLI 未连接 / `51002` 积分不足 / `51003` 审核未通过 / `51004` 生成超时 / `51005` 生成被中断等），后端 `message` 优先、为空时兜底。四态（骨架屏 / 空态 / 错误态带重试 / 降级）在每个数据区块强制实现。

## 9. 已知边界（与 README 一致）

1. **素材删除不可恢复且不留痕**：`DELETE /assets/{id}` 同时删除素材记录与磁盘图片文件，且不写 `records` / `logs`，误删后无法追溯；`db.json.bak-*` 轮转备份只保记录、不保图片；
2. 分页控件未做（接口签名已按契约实现）；
3. 无鉴权流程（`token` 由 `APP_CONFIG` 注入，401 只 Toast 不跳登录）；
4. 无虚拟滚动（大数据量建议紧凑视图，契约第 9 章建议 >50 行启用）;
5. 素材导入的**名称匹配只按文件名 / 段首关键词**，不做语义匹配：图片文件名与资产名不一致时不会自动挂载；提示词分段依据是**单独一行的 `@`**，段首缺类型标识词（角色 / 场景 / 道具）的段会被跳过；
6. 真实生成需要已开通权限的即梦账号（非会员被服务端闸门拒绝，任务以 `40300` 给出明确原因）。

## 10. 快速开始

```bash
cd jimeng-console
node server/index.js                # 1. 启动后端（唯一启动步骤，零依赖）

node build.js                       # 修改 app/ 后重建发布版
dist/即梦批量生成控制台.html          # 发布版双击打开，自动连本机后端
```

2. 浏览器打开 **http://127.0.0.1:8787/**（前端由后端托管，同源直连）。
3. 可选配置：在 `app/index.html` 引入脚本**之前**插入 `window.APP_CONFIG = { baseUrl: '...', token: '...', projectId: 'pj_1' }`（发布版需重新构建）。
