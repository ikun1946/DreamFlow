## 0. 三十秒版

- **它是什么**：一个**本地运行**的批量视频生成工作台。前端管分镜（导入 / 绑定素材 / 提交 / 看进度），后端调**即梦官方创作 CLI（`dreamina`）**真正出片。
- **一份代码，两种交付**：网页版（`node server/index.js` → `http://127.0.0.1:8787/`）与 Windows 桌面版（Electron 壳内嵌同一个服务，随机端口 + 一次性 Token）。
- **硬约束**：**零运行时依赖** —— 后端只用 Node 内置模块，前端是原生 HTML/CSS/JS；`electron` / `electron-builder` 只是**打包期**依赖。
- **数据在哪**：网页版在 `server/data/`；桌面版在 `%USERPROFILE%\Videos\JimengConsole\`（可改）。**数据一律不入 git**。
- **不能做的事**：不内置任何第三方二进制（授权未确认）；不把安装包提交进 git；不用真实数据做测试。
- **当前版本**：`0.35.7`。发版流程另见 `docs/版本发布与更新流程.md`。
  > ⚠ 版本号以 `package.json` 为**唯一生效来源**；本行与 README「当前版本」必须同步。
  > 手动改容易漂移（历史上本行曾落后两个版本），`npm run check` 会直接报错拦住。

## 1. 项目定位与类型

### 1.1 一句话定位

**面向 AI 短剧 / 分镜视频生产的「批量管理 + 真实生成」工作台**：把一个批次的多个分镜提示词集中管理，绑定素材（角色 / 场景 / 道具 / 首帧图 / 分镜图 / 音频参考），批量提交给即梦创作 CLI，轮询进度并归档产物。

### 1.2 它解决什么问题

即梦官方只提供**单条**命令行调用（`dreamina text2video ...`）。真正做一部短剧时，用户面对的是几十上百条分镜 —— 手工一条条敲命令、盯进度、找产物、记结果，成本极高。本应用把这件事变成：

| 痛点 | 本项目的做法 |
|---|---|
| 一条条敲提示词 | 批量导入（粘贴多段文本，按分隔符自动切分，带预览确认） |
| 一条条配素材 | 素材库（按项目共享）+ 单条绑定 / 自动匹配 / 批量绑定 |
| 一条条提交、盯进度 | 批量提交（幂等）+ 队列 worker + 进度轮询（3s→6s→10s 退避） |
| 产物散落各处 | 按项目 / 分镜归档到磁盘，前端可直接预览播放 |
| 事后不知道跑过什么 | 生成记录（成功 / 失败 / 取消 / 干跑各落一条快照）+ 执行日志 |
| 多部剧混在一起 | 多项目 / 多工作区隔离（项目级素材库 + 工作区分镜表） |

### 1.3 它不是什么（边界要清楚）

- **不是云服务 / 不是 SaaS**：服务只监听 `127.0.0.1`，所有数据在本机磁盘上。
- **不是演示项目**：**空库启动，无任何模拟数据**；所有数据来自真实导入 / 接口创建 / 真实生成。唯一的「假执行」是**干跑模式**（`JC_DRY_RUN=1`），它只组装命令不派发，用于核对参数。
- **不是通用视频编辑器**：不做剪辑、合成、转场；产物由即梦生成，本应用只负责调度与归档。
- **不自带生成能力**：没有 CLI 就完全不能出片（所以 0.23.0 专门做了应用内一键安装 CLI）。

### 1.4 两种交付形态（共用同一份业务代码）

| | 网页版 | Windows 桌面版 |
|---|---|---|
| 入口 | `server/index.js` | `desktop/main.js`（Electron 主进程） |
| 启动命令 | `node server/index.js` | 开发态 `npm start`；出包 `npm run dist` |
| 服务 | `index.js` → `server/server.js` | 主进程内嵌调用 `server/server.js` |
| 端口 | 固定 `127.0.0.1:8787` | **`port: 0` 随机空闲端口**（避免与网页版抢 8787） |
| 鉴权 | 默认无 Token（`token` 为空不校验） | **每次启动生成一次性 Token**，请求须带 `Authorization` |
| 前端来源 | 后端托管 `app/`，同源 `/api/v1` | 同样由后端托管，但**显式禁用 `file://` 来源** |
| 数据根 | `server/data/` | `%USERPROFILE%\Videos\JimengConsole\`（可改，见 §6.5） |
| 壳能力 | 无 | 托盘、单实例、外部工具定位、旧数据导入、应用内自更新、日志落盘 |
| 更新方式 | `git pull` | 应用内自更新（0.24.0+） |

**共用**：`app/`（前端）与 `server/`（业务与接口）**一行代码都不分叉** —— 这是刻意设计，避免两套实现漂移。

### 1.5 六条硬约束（违反会出事故）

| # | 约束 | 原因 |
|---|---|---|
| 1 | **零运行时依赖** | 后端只用 Node 内置模块，前端原生 JS。往 `dependencies` 加运行时库会破坏「克隆即可跑」的部署方式 |
| 2 | **不内置任何第三方二进制** | `dreamina.exe` 再分发授权未确认；FFmpeg 是 GPL 构建且单个约 212 MB。两者都改为**运行时获取 / 可选依赖** |
| 3 | **数据只写用户可写目录** | 装到 `Program Files` 后安装目录只读。桌面版数据根在用户目录（`desktop/runtime-paths.js` 是唯一出口） |
| 4 | **安装包只走 GitHub Releases** | `release/` 是上百 MB 的产物，已 gitignore；进 git 会把仓库撑爆且不可逆 |
| 5 | **不用真实数据做测试** | 测试一律用 `JC_DATA_DIR` 指到临时目录，绝不碰 `server/data/` 与用户的真实库 |
| 6 | **前后端分层不许破** | 前端 `api.js` 不碰 DOM、`app.js` 不拼 URL；后端作用域一律 **request-scoped**（后端不存在「当前项目」这种全局状态） |

## 2. 整体结构

### 2.1 运行时拓扑

```
┌──────────────────────── 浏览器 / Electron 窗口 ────────────────────────┐
│  app/index.html  页面骨架                                              │
│  ┌───────────────┐   消费 Api 对象   ┌────────────────────────────┐    │
│  │   app.js      │ ───────────────→ │  api.js                    │    │
│  │ 状态/渲染/交互 │                   │  接口层（唯一后端耦合）      │    │
│  │ /轮询/乐观更新 │ ←─────────────── │  统一信封 + ApiError        │    │
│  └───────────────┘   数据 / 错误     └─────────────┬──────────────┘    │
└────────────────────────────────────────────────────┼───────────────────┘
                                                     │ HTTP /api/v1
                        ┌────────────────────────────▼──────────────────┐
                        │  server/server.js  （可嵌入服务：createServer │
                        │  / start / stop；静态托管 + 路由 + 队列）      │
                        │   ├── routes.js     路由表（56 条）            │
                        │   ├── services.js   业务逻辑（最大模块）        │
                        │   ├── projects.js   项目/工作区 + 作用域解析    │
                        │   ├── store.js      JSON 持久化（原子写）      │
                        │   ├── worker.js     队列派发 + 写入守卫        │
                        │   └── dreamina-cli.js  创作 CLI 适配层         │
                        └───────┬───────────────────────────┬───────────┘
                                │ spawn                     │ 读写
                    ┌───────────▼───────────┐   ┌───────────▼─────────────┐
                    │ dreamina.exe（官方）   │   │ db.json + projects/<id>/ │
                    │ %USERPROFILE%\bin\     │   │   assets/  output/       │
                    │ 创作 CLI，唯一生成引擎 │   │ （用户数据，不入 git）    │
                    └───────────────────────┘   └─────────────────────────┘
```

### 2.2 分层铁律

写在文件头部、并被反复强调的约定：

- **`app/api.js` 不碰 DOM**：只负责「请求 → 数据 / `ApiError`」。
- **`app/app.js` 不拼 URL**：只负责「数据 → DOM」与用户操作，一律通过 `Api.xxx()`。
- **后端不做「当前项目」**：项目 / 工作区由 URL 或查询串携带，后端**校验父子关系**后过滤（作用域解析唯一出口在 `server/projects.js`）。
- **每类事实只有一个出口**（见 §4.2）：模型名、状态迁移、磁盘布局、schema 版本都各有唯一来源模块，禁止就地硬编码。

### 2.3 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 页面 | 原生 HTML5 | 单页，`lang="zh-CN"`，无路由框架 |
| 样式 | 原生 CSS | 设计令牌集中在 `styles.css` 的 `:root`，支持深色模式 |
| 逻辑 | 原生 JavaScript（ES2017+） | IIFE 模块，无打包器；`api.js` 挂 `window.Api` |
| 请求 | `fetch` | 统一信封 `{ code, message, data, traceId }`，`code !== 0` 即业务失败 |
| 构建 | Node `fs`/`path`（`build.js`） | 只做文本内联，零依赖 |
| 后端 | Node 内置模块（`server/`） | 零 npm 依赖，Node ≥ 20 |
| 桌面壳 | Electron（**仅打包期依赖**） | 主进程 + `contextBridge` 最小权限桥 |
| 打包 | electron-builder → NSIS | 出 Windows x64 安装包，`perMachine: false` 不弹 UAC |
| 生成引擎 | 即梦创作 CLI（外部） | 运行时从官方 CDN 安装到 `%USERPROFILE%\bin\dreamina.exe` |

### 4.1 服务端模块依赖图（`require` 实测）

### 4.3 前端（`app/`）—— 分层与内部模块

### 4.6 前端实现要点（页面 / 控件 / 轮询 / 乐观更新 / 错误文案）

**P1 主界面 · 分镜表**

- **表格 10 列**：序号 / 分镜·提示词（含时长控件与参数行）/ 角色 / 场景 / 道具 / 首帧图 / 分镜图 / 结果与进度 / 状态 / 操作。列宽由 `COLUMNS` 配置驱动，列头由 JS 生成。
- **素材槽位规则**：角色列可多个（最多展示 2 + 「＋」），场景 / 道具 / 首帧图 / 分镜图各 1 个；单值槽位有值时「＋」消失；缩略图为由 ID 派生的稳定渐变（离线可跑，不依赖外部图片）。
- **状态机**：`queued（排队中）→ generating（生成中）→ succeeded（已完成）/ failed（失败）`，另有 `canceled（已取消）`。`status` **只由后端下发**，前端不做状态推断。
- **勾选与批量**：勾选后底部状态栏出现「批量改时长 / 删除所选 / 取消选择」，素材面板出现「提交所选 N」。
- **紧凑视图**：顶栏一键切换行高 210px ↔ 132px（CSS 变量整体缩放缩略图尺寸）。
- **详情弹层**：完整参数、远端 ID、重试次数、失败原因、**将要执行的 CLI 命令**回显、执行日志。
- **产物预览**：点击已完成行的结果缩略图，弹层展示封面渐变 + 视频地址（`videoUrl`）。

**P2 批量导入提示词**

- 粘贴多段文本 → 防抖 400ms 自动调预览接口 → 按 `;;` / 竖线 / `---` / 换行 / 自定义分隔符拆分 → 实时显示「已识别 N 段，将创建 N 个分镜」+ 逐段预览（重复 / 超长标注）。
- 拆分规则与后端必须一致：**不裁剪段内空格、只 trim 首尾、丢弃空段**（`splitSegments()`）。
- 确认导入：带 `Idempotency-Key` 防重放；新行插入表格并自动勾选，可直接批量提交。

**P3 设置面板（一份 DOM，三种形态）**

- 四个分组：提示词分隔符（与 P2 同源数据，此处保存为持久默认）、生成参数默认值、队列与执行（并发 1–5、失败自动重试最多 2 次）、接口对接（CLI 状态与登录 / 切换账号）。
- **CLI 登录 / 切换账号是同一个入口**（2026-09-23 / 0.35.5 起）：未登录时显示「登录账号」，已登录时显示「切换账号」。判据用 `dInfo.available`（CLI 可用且登录态有效），**不是**"有没有账号信息"—— 后者在探测失败时为空，会把已登录的人误判成未登录。合并前两个按钮并排，未登录的人会看到「切换账号」（没账号可切），已登录的人会看到「登录」（易误以为要重复授权）。
- CLI 未就绪时显示琥珀色状态卡「任务将入队但不执行」；`batch-submit` 在 CLI 不可用时直接返回 `51001` 拒绝。
- 保存走 `PUT /settings` 全量提交（`40001` 返回 `data.fields[]` 行内校验信息）；恢复默认支持按 scope（delimiter / defaults / queue）部分重置。
- **形态随入口不同（2026-09-23 / 0.35.0 起）**，共用同一个 `#settingsDrawer` 与同一套渲染逻辑，只换形态：

  | 入口 | 形态 | 类名 | 尺寸 |
  |---|---|---|---|
  | 首页（项目墙）顶栏「设置」 | **居中弹窗** + 压暗遮罩 | `.drawer.center` | 820px × 88vh，圆角 18px |
  | 分镜表顶栏「设置」 | 右侧抽屉（原有） | `.drawer` | 480px，全高 |
  | 项目主页「设置」页签 | 就地铺满（原有） | `.drawer.inline` | 100% × 100%，无遮罩 |

  选居中而非"横铺满整屏"的理由：横铺需要新增第 4 个 pageview 与配套返回栈，与现有三层视图导航语义打架；居中弹窗复用现有 DOM，改动面最小。
  ⚠ 三处易错点（都写在 `styles.css` 的 `.drawer.center` 注释里）：① 换形态必须先 `hidden` 再改类，否则窗口会从抽屉位横扫到屏幕中央；② 遮罩要抬到 `z-index:66`（首页 `.pageview` 是 65，否则遮罩被压在底下）；③ `.center` 与 `.inline` 互斥（`.inline` 复位不了 `opacity`/`max-height`/`border-radius`，同时生效会让就地面板变透明）。

**进度轮询（前端最重要的机制）**

| 项 | 实现 |
|---|---|
| 触发条件 | 列表中存在 `generating` / `queued` 行 |
| 接口 | `GET /storyboards/progress?ids=...`（单次上限 50 个 ID，前端切片） |
| 增量语义 | 后端**只返回有变化的项**，无变化返回 `[]` |
| 退避 | 基线 3s；连续 3 次无变化 → 6s → 10s 封顶；异常指数退避封顶 30s（`42900` 不弹错） |
| 暂停 / 恢复 | 页面隐藏暂停；恢复可见立即拉一次 |
| 停止 | 全部活跃任务进入终态 |
| 收口 | 任一行到达终态时重拉列表，以服务端统计为准 |
| 视觉 | 进度条 350ms 线性过渡（CSS），服务端跳变不闪烁 |

**乐观更新策略**

- **改时长**：立即生效 → 300ms 防抖合并为一次 `PATCH` → 失败回滚原值 + Toast（`40900` 已完成锁定）。
- **批量提交**：`accepted[]` 项立即置 `queued` 并启动轮询；`rejected[]` 项行内红条展示原因。
- **删除 / 重排**：不做乐观更新，服务端确认后生效。

**错误处理与文案**

统一信封 `{ code, message, data, traceId }`；`app.js` 的 `ERR_TEXT` 提供兜底文案表（`51001` CLI 未连接 / `51002` 积分不足 / `51003` 审核未通过 / `51004` 生成超时 / `51005` 生成被中断等），后端 `message` 优先、为空时兜底。四态（骨架屏 / 空态 / 错误态带重试 / 降级）在每个数据区块强制实现。

**首页 / 项目主页（非分镜表的三个视图）**

- 三个 pageview（`#homeView` 首页 / `#projView` 项目主页 / `#recView` 生成记录）是 `#app` 的**兄弟节点**，`position:fixed` 铺满、靠 `[hidden]` 切换；`#app` 启动时先挂 `hidden-view`，等 `setView()` 按 URL 决定显示哪一层（不藏会先闪一帧空表格）。
- **设置面板三个视图都能打开**：首页顶栏「设置」（2026-09-21 补上 —— 此前只有进了项目页才够得着）、项目主页的页签、分镜表顶栏「设置」。面板对空库是安全的：`openSettings` 里三个请求各自 `catch`，取不到就渲染占位。**三者形态不同**（首页居中弹窗 / 分镜表右侧抽屉 / 项目页就地铺满），详见 §4.6 的「P3 设置面板」。

### 4.7 构建脚本 `build.js`：内联与四道校验

把 `app/` 四文件 + 应用内图标按锚点内联为 `dist/即梦批量生成控制台.html`，内置四道校验（任一道不过就报错退出）：

1. 源码中不得有字面量的脚本结束标签（防止内联时提前截断脚本块）；
2. `app/index.html` 必须存在样式锚点与脚本锚点（脚本两行相邻、以 `\n` 分隔）；
3. `String.replace` 必须用**回调函数**形式 —— 字符串形式会把 `$$` / `$&` 当替换占位符吞掉，产物静默损坏（实际踩过的坑）；
4. 产物后置校验：`$$` 数量一致、脚本块数 = 原有内联脚本数 + 2、样式块恰 1 个、无残留外部引用。

另有一处**内联**（不是校验）：`app/icon.png` 会被换成 data URI —— 单文件版是 `file://` 打开的，旁边没有 `icon.png`，不内联就是 favicon 与顶栏品牌标两个裂图；产物里残留 `="icon.png"` 同样会被拦下。

## 5. 主要流程

### 5.1 网页版启动

1. `node server/index.js` → `loadConfig()`（环境变量 → `server/config.json` → 默认）。
2. `createServer({ config })` → `start()` → `listen(8787, 127.0.0.1)`。
3. 打印横幅（API 地址 + 应用首页地址）。
4. 浏览器打开 `http://127.0.0.1:8787/` → 服务托管 `app/`，页面同源请求 `/api/v1`。
5. `Ctrl+C` → 同一个 `stop()` 优雅收尾（落盘 + 收子进程）。

### 5.2 桌面版启动（`desktop/main.js`）

1. **单实例锁** + 设置 AppUserModelId（托盘 / 任务栏归组）。
2. **解析目录布局**（`runtime-paths.js`）：读 `%APPDATA%\<产品名>\desktop-config.json` → 定数据根（默认 `%USERPROFILE%\Videos\JimengConsole\`）；数据根**写不进去**时退回 `userData\data` 并提示（**绝不悄悄用空库启动**）。
3. **接管 console → 落盘日志**（`logger.js`，2 MB 轮转）。
4. **定位外部工具**（`external-tools.js`）。
5. **旧数据导入引导**（仅首次，`legacyImportChecked` 标记）：发现旧版 `server/data` 就询问是否导入 —— 复制 + 体检，**原目录保留**。
6. **注入运行时配置**（`runtime.configure()` + `loadConfig({ port: 0, token })`）→ 起内嵌服务 → 拿到**随机端口**与**一次性 Token**。
7. 开窗口（指向 `http://127.0.0.1:<随机端口>/`）、建托盘、设置外部链接策略（外部链接一律交系统浏览器）。
8. 退出：先 `server.stop()`（落盘 + 收子进程，避免 `dreamina` 变孤儿），再退出。

> ⚠️ **自动化测试真实应用的坑**：首次启动会弹「旧数据导入」对话框并**阻塞窗口创建**。测试前必须先让 `desktop-config.json` 里 `legacyImportChecked: true`，否则调试端口 `/json` 会一直返回 0 个目标，看起来像「应用起不来」。

### 5.3 生成链路（本项目的主线）

```
① 批量导入提示词        前端粘贴 → 防抖 400ms → POST /storyboards/import/preview（只预览）
   （P2 导入弹层）              → 用户确认 → POST /storyboards/import（带 Idempotency-Key）
② 绑定素材              素材面板选卡 → POST /storyboards/{id}/assets（role 即素材类型）
   （角色可多个，其余单值）      → 也可 POST /storyboards/auto-assets 按素材名自动匹配
③ 批量提交              POST /storyboards/batch-submit（幂等；CLI 不可用时直接拒绝）
                              → 受理项立即置 queued，前端启动轮询
④ 队列派发              worker.tick()：并发闸（本地保护上限，默认不限）→ 只派发 queued
⑤ 真正执行              spawn dreamina（创作 CLI）→ 拿 submitId → 轮询 query_result
   （dreamina-cli.js）          每次写入都要过「写入守卫」（attemptId 校验，防旧结果覆盖新状态）
⑥ 产物归档              视频 / 封面落到 projects/<projectId>/output/<storyboardId>/
   （paths.js 决定形状）        ffmpeg 抽帧做封面（没装就跳过）
⑦ 结果回写              写 db.json（原子写）+ 落一条生成记录（records.js）
⑧ 前端收口              GET /storyboards/progress?ids=...（单次 ≤ 50 个，前端切片）
                              → 只返回有变化的项；出现终态则重拉列表校准统计
```

**失败与重试**：`worker.mapTaskError` 做失败分类，自动重试受 `settings.queue.autoRetry / maxRetry` 约束；每条失败都落生成记录，详情弹层可看**将要执行的完整命令**与执行日志。

**干跑**：`POST /storyboards/{id}/dry-run` 只组装命令不派发（服务级干跑见 `JC_DRY_RUN=1`），用于核对参数、零积分消耗。

### 5.4 素材流程

| 环节 | 接口 / 位置 | 要点 |
|---|---|---|
| 上传 / 导入 | `POST /assets/upload`（原始字节，`?type=&name=`） | 素材名默认取文件名去扩展名 |
| 只建元数据 | `POST /assets` | 先建记录，文件之后由 `/assets/{id}/file` 补 |
| **导入预览** | 前端「导入资产」弹层 | 落库**前**出清单：每行显示去向（补图 / 覆盖 / 新增 / 跳过）、可改类型、可手动关联已有素材 |
| 匹配规则 | `services.js` | **精确同名**（去扩展名后逐字相等）——「白色信封」不会自动配上「信封」；不做模糊 / 语义匹配，是否关联由用户在预览里决定 |
| 改类型 | `PATCH /assets/{id}`（`type`） | 必须**同 kind**（图片↔音频互转被拒）；类型真的变化时**解除该素材在本项目全部分镜上的绑定**并返回 `unbound` |
| 查引用数 | `GET /assets/{id}/usage` | 改类型前提示「已被 N 条分镜引用」的准确数据来源 |
| 删除 | `DELETE /assets/{id}` | ⚠️ **连磁盘图片一起删且不留痕**，不可恢复 |

### 5.5 创作 CLI 的安装 / 更新（`server/cli-installer.js`）

- **为什么需要**：官方唯一安装方式是 `curl -s https://jimeng.jianying.com/cli | bash`，其 Windows 分支要求 MINGW / MSYS / CYGWIN（即 Git Bash）—— **干净的 Windows 跑不了**，没装 CLI 的用户完全用不了本应用。
- **做法**：替用户做官方脚本本来就会做的事 —— 从**官方 CDN** 下载官方二进制，装到官方脚本的默认位置 `%USERPROFILE%\bin\dreamina.exe`。
- **三条不能破**：① 绝不把二进制打进安装包（再分发授权未确认）；② 装到官方默认位置（避免「手工装 / 应用装」两份互不知道）；③ 更新前备份旧文件、下载后**校验是合法 PE**（CDN 出错可能返回 HTML 错误页）。
- **两个容易搞混的判据**：「装没装」看 **spawn 能不能起来**（不是看某个文件在不在）；版本号有**两个来源** —— exe 自己报的是 commit（`dreamina version`），官方 `version.json` 报的是语义版本。

### 5.6 应用内自更新（`desktop/updater.js`）

检查 → 下载 → 校验 → 静默安装 → 自动重启。**为什么不用 `electron-updater`**：自更新只需要「知道最新版、下载、调安装器」三件事，而 electron-builder 的 NSIS 安装器本来就支持这三个开关，本仓库坚持零运行时依赖。

**四条硬约束**：① 网络源**只接受 https**（更新源已固定为 github，允许 http 等于让链路上任何人替换「会被执行的 exe」）；② 下载后**必须校验 sha512**（`latest.yml` 里的哈希，边下边算；**清单里没有 sha512 就整份拒绝** —— 2026-09-22 补，原先会静默跳过校验，等于"无校验安装"）；③ 安装器必须用 **`/S --updated --force-run`**（少 `--updated` 可能删用户数据；少 `--force-run` 装完看不到变化；少 `/S` 会弹安装界面）；④ **令牌只进不出**（`update:status` 只回传 `hasToken`，不把密钥回传页面）。

**更新源三种模式**（`updater.resolveSource()` 仍全部支持，但**应用只传内置默认值**，所以实际生效的恒为第一种）：`github`（**唯一生效**；本仓库已公开、匿名可读、无需令牌）/ `url`（公开 CDN 或自建静态站）/ `local`（离线、内网、开发机自测 —— 本地目录也要「复制 + 校验」，校验与执行之间不留时间窗）。后两种只被 `test/03-build-release.test.js` 直接调用 `updater.download()` 覆盖。

> ⚠ **2026-09-23：更新源已固定，使用者无法更改。** `updateSource()` 恒返回内置的 `DEFAULT_SOURCE`（`github` / `ikun1946` / `DreamFlow`），**不再读 `desktop-config.json` 的 `updates` 段**（该键已失效），也不再读任何环境变量。界面上仍**显示**当前更新源（`publicSource`），只是没有任何修改入口。
>
> **为什么不能只把界面入口拿掉**：`desktop-config.json` 是纯文本、就在使用者自己的 `%APPDATA%` 下，任何人手改 `updates` 段仍能把它指向别的 https 地址或本地目录 —— 而更新链路的终点是「下载并执行一个安装器」。只删界面等于"锁了门却留着窗"。把来源钉死，这条路径才真正消失。
>
> ⚠ **代价（必须知道）**：`scripts/test-update-flow.ps1` 的离线能力随之失去 —— 它依赖配置注入本地源（虽然实测那个注入本就写错了位置，见 `desktop/main.js` 里 `JC_UPDATE_FLOW_TEST` 段的注释），现在只能跑**在线 GitHub 源**，需要联网且会真下载一个上百 MB 的安装包。本地源（`local`）的覆盖在 `test/03-build-release.test.js` 里走 `updater.download` 直测。

**互斥状态机**（`desktop/update-state.js`，2026-09-22 从 `main.js` 抽出）：更新有两个入口（设置页 IPC 与托盘菜单），修复前两条路能同时开跑 —— 连点两次「检查更新」会互相覆盖结果、检查/下载期间点安装会拿到半截文件、重复下载会写同一个 `.part-<pid>`。现在所有入口统一走 `withLock(action, fn)`：五态 `idle / checking / downloading / ready / installing`，拿不到锁的直接返回 `{ ok:false, busy:true }`（界面静默处理，不弹错误框）。抽成独立模块的原因很实际：埋在 `main.js` 里时只能靠**匹配源码文本**来测（改名会误报、行为退化却会漏报），抽出来后可以直接调用它做行为测试 —— 一抽出来就抓到"安装成功后立刻复位 `installing`，导致 800ms 退出窗口里能拉起第二个安装器"这个真缺陷。

## 7. 数据与存储

### 7.1 `db.json` 结构（`store.emptyDb()`）

| 键 | 内容 |
|---|---|
| `schemaVersion` | 当前 `3`（`schema.js` 是唯一出口） |
| `projects` / `workspaces` | 项目与工作区（**空库不预置任何项目** —— 全新安装应该是空的项目墙 + 「创建项目」） |
| `storyboards` | 全部分镜（含 `projectId` + `workspaceId`） |
| `assets` | 素材（**项目级**：同一项目的所有工作区共享一份素材库） |
| `settings` | `delimiter`（分隔符）、`defaults`（模型 / 画幅 / 分辨率 / 时长 / 运动强度）、`queue`（并发 / 自动重试）、`adapter`（CLI 状态） |
| `seq` | ID 自增序列 |
| `idempotency` | 幂等键 → 已执行过的响应（防重复提交 / 重复扣费） |
| `cliJobs` | 每条分镜的 CLI 任务上下文（`submitId` / 状态 / 命令 / 归属） |
| `logs` | 每条分镜的执行日志 |
| `records` / `recordSeq` | 生成记录（追加式快照，新记录在前） |

### 7.2 落盘策略（`store.js`）

- **原子写**：临时文件 + `rename`（Windows 下避免半截文件）。
- **损坏隔离**：`db.json` 读不出来时先另存为 `.corrupt-<时间>` **再**重建 —— 杜绝「静默清空」。
- **轮转备份**：`db.json.bak-<时间>`（只保记录，**不保磁盘图片**）。
- **防抖保存**：高频写入合并落盘。

### 7.3 项目 / 工作区隔离

- **素材属于项目**：同一项目的所有工作区分镜共用素材库。
- **分镜属于工作区**：分镜表按工作区隔离。
- **后端一律 request-scoped**：每个请求显式带 `projectId` / `workspaceId`，后端校验父子关系（`projects.js`）。后端**没有**「当前项目」全局状态。
- **删除两条路**：默认**软删除**（只标 `deletedAt`）；`?hard=1` 才**彻底删除**（连磁盘文件、分镜、素材、记录一起抹掉，**不可恢复**）。两条路都受「有活动任务则拒绝」的保护。

### 7.4 不可恢复 / 高风险操作

| 操作 | 风险 |
|---|---|
| `DELETE /assets/{id}` | 素材记录 + **磁盘图片**一起删，**不留痕**、不进记录 |
| `DELETE /projects/{id}?hard=1` | 项目、分镜、素材、产物、记录全删，不可恢复 |
| 手动改 / 删 `db.json` | 唯一数据库；误删等于丢掉全部分镜与记录 |
| 把 `JC_DATA_DIR` 指向真实库做测试 | 测试数据会写进真实库（**测试必须用临时目录**） |

## 8. 接口概览

**统一约定**：所有接口挂在 `/api/v1` 下；响应信封 `{ code, message, data, traceId }`，`code !== 0` 即业务失败；作用域由 `projectId` / `workspaceId`（查询串或路径）携带；写接口支持 `Idempotency-Key` 防重放。

**路由表实测 56 条**（`server/routes.js`；按「一个正则 = 1 条」计，若按「路径 + 方法」组合计则为 58 条），按功能分组：

| 分组 | 代表接口 | 说明 |
|---|---|---|
| 元信息 / 鉴权 | `GET /meta/options`、`GET /auth/me` | 选项枚举、当前用户 |
| 系统 / CLI | `GET /system/adapter`、`GET /system/cli`、`POST /system/cli/install`、`POST /system/adapter/check`、`.../dreamina/login`、`.../dreamina/switch` | CLI 状态、一键安装、账户检查与登录切换 |
| 数据目录 | `GET /runtime/paths`、`POST /runtime/data-dir` | 查看 / 切换数据根（迁移并切换或仅切换）；**改完需重启才生效** |
| 项目 / 工作区 | `GET|POST /projects`、`GET|PATCH|DELETE /projects/{id}`、`/projects/{id}/workspaces`、`/workspaces/{id}` | 含软删 / `?hard=1` 硬删 |
| 分镜 | `GET|POST /storyboards`、`GET|PATCH /storyboards/{id}`、`/storyboards/progress` | 兼容旧式扁平路径与项目 / 工作区路径两种形态 |

## 9. 完成一项工作后的固定动作（收尾清单）

> 这一节与 `AGENTS.md` 的「完成一项工作后的固定动作（Definition of Done）」**内容一致**。
> `AGENTS.md` 是 agent 自动加载的入口，因此**改这里请同步那边**（见 §13）。

**每完成一件工作，收尾时按这个清单走一遍。顺序有意义，别跳步。**

1. **改完 `app/` 必须重建网页版**：`node build.js`。脚本自带校验（`$$` 是否被吞、script/style 块数量、有无残留外部引用），不通过会报错退出。忘了这步，`dist/` 里留的就是旧代码。
2. **真跑一遍才算完成**：`npm run verify`（check + test + build）全绿只是**入场券**，**「语法通过」不等于「能用」**。改 UI 就 `npm start` 或跑 `npm run smoke:web` / `npm run e2e` 实际点一遍；改后端就发真实请求验证。**不要把「应该能跑」当结论。**
3. **更新版本号（两处三地）**：`package.json`（唯一生效来源）+ `README.md` 的「当前版本」+「变更记录」。新增能力 → MINOR，修缺陷 / 改文档 → PATCH。
4. **写变更记录**：在 README「变更记录」顶部加一段。**写清「为什么改」和「踩过什么坑」**，不要只写「优化了 X」—— 这段是后来者唯一的上下文来源。
5. **同步受影响的文档**：改了接口 → 更新 `docs/前端页面与接口对接说明.md`；改了发布方式 → 更新 `docs/版本发布与更新流程.md`；**任何会改变架构描述的改动，都要在 `docs/更改文档.md` 留痕**（这份文档历史上就因为漏记而落后过好几个版本，2026-09-21 才补回来）；**改了本清单本身 → 同步 `AGENTS.md` 与本文 §9 两处**（两处内容必须一致，不一致时以 `AGENTS.md` 为准）。
6. **提交并推送**：`git add -A` → `git commit` → `git push origin main`。
7. **发版（可选，取决于是否要交付给使用者）**：见 `docs/版本发布与更新流程.md`。两个最容易忘的点：tag **必须单独 push**（`git push origin vX.Y.Z`，普通 push 不推 tag）；安装包只走 GitHub Releases，**绝不进 git**。

> ⚠️ **「做完但还没发版」也要在第 3 步登记版本号** —— 否则会出现「代码已经在 main 上、却没有任何版本号」的状态。2026-09-21 真实发生过一次（导入资产预览那批）。发版与否是第 7 步单独决定的，不影响第 3 步。

### 9.1 收尾清单的存放位置（回答「会不会随项目上传到 Git」）

| 问题 | 答案 |
|---|---|
| 会随项目上传到 Git 吗？ | **会。** 清单写在仓库根 `AGENTS.md`（git 跟踪，`git ls-files` 可见），随 `git push` 一起进远端 |
| 文件位置与命名 | 仓库根目录 `AGENTS.md`（**大写**，无扩展名以外的后缀）；章节名「完成一项工作后的固定动作（Definition of Done）」 |

## 10. 已知边界与发布阻塞项

### 10.1 功能边界（与 README 一致）

1. **素材删除不可恢复且不留痕**：`DELETE /assets/{id}` 同时删记录与磁盘图片，且不写 `records` / `logs`；`db.json.bak-*` 只保记录、不保图片。
2. **分页控件未做**（接口签名已按契约实现）。
3. **无鉴权流程**：`token` 由 `APP_CONFIG` 注入，401 只弹 Toast 不跳登录页。
4. **无虚拟滚动**：大数据量建议用紧凑视图。
5. **素材匹配只按精确同名**，不做语义匹配；提示词分段的类型标识依赖段首关键词。
6. **真实生成需要已开通权限的即梦账号**（非会员被服务端闸门拒绝，返回明确原因）。
7. **`--audio` 的效果未经实测验证**（README 有专门说明）。

> 注：曾有一版「GPT / DALL·E 图生」（`server/revchatgpt.js`）在制品，**从未提交、从未发布、前端无入口**，
> 2026-09-23 已按使用者要求整体移除（见 `docs/CHANGELOG.md` 的 `0.35.1`）。此处不留条目 —— 它不属于本项目的功能边界。

### 10.2 发布阻塞项（**尚未解决**，对外公开分发前必须处理）

| # | 阻塞项 | 现状 |
|---|---|---|
| 1 | 仓库**没有 `LICENSE`** | 未定 |

## 11. 事故注释索引（代码里那些「为什么」）

本仓库的注释刻意记录**踩过的坑**（不许删）。按位置索引：

| 位置 | 记录的事故 / 教训 |
|---|---|
| `build.js` | 字符串形式的 `String.replace` 会把 `$$` / `$&` 当占位符吞掉 → 产物静默损坏；内联前必须检查字面量 `</script`（否则脚本块被提前截断） |
| `server/store.js` | 曾因**空库覆盖真实数据**且无从追查 → 现在损坏库先隔离成 `.corrupt-<时间>` 再重建 |
| `server/schema.js` | 迁移曾**藏在只读接口里**（`GET /meta/options` 顺手改写全库并 save），靠用户打开页面才触发 → 收敛为「读版本 → 按序迁移 → 校验 → 写版本」，且只在克隆体上跑 |
| `server/runtime.js` / `server/paths.js` | 曾出现「以为重定向了数据根、其实一路写进真实目录」→ 现在数据根**调用时读取**，且集中在一处 |
| `server/server.js` | 静态文件曾整块读入内存、不返回 206 → 大视频顶住事件循环、浏览器无法拖进度条；现按 HTTP Range 流式返回 |
| `server/worker.js` | 写入守卫：旧任务的迟到结果会覆盖新状态 → 每次派发抓 `attemptId`，此后所有写入先过闸 |
| `services.js`（0.25.0） | `deleteAsset` 原用**工作区级**解绑 → 同项目其它分镜表留下悬空 `assetId`；改用项目级 `projectStoryboards` |
| `desktop/main.js`（首次启动） | 旧数据导入对话框会**阻塞窗口创建** → 自动化测试前必须先置 `legacyImportChecked: true`，否则调试端口 `/json` 返回 0 个目标 |
| `server/cli-installer.js` | 「装没装」曾靠读 `~/.dreamina_cli/version.json` 判断 → exe 不存在也报「已安装」，把用户引去查登录问题；现以 **spawn 能否起来**为准 |
| `desktop/updater.js` | 自更新三条开关缺一不可（`/S` `--updated` `--force-run`），依据是 electron-builder 的 NSIS 模板源码 |
| `server/server.js`（`ICON_ANCHOR`） | 页面挂在 `/` 上，服务端本来就把 `styles.css` / `api.js` / `app.js` 改写成 `/app/...`；2026-09-21 新加的 `icon.png` 漏了这条改写 → 浏览器请求 `/icon.png` 直接 404，表现是**两个裂图**。冒烟自检的资源日志（`res` 字段）里能直接看到 `icon.png=404` |
