# 图片资产 GPT 生图：实施计划与操作流程

> 状态：**待实施的设计方案**，文中拟议按钮与接口目前尚不存在。
>
> 制定日期：2026-09-25；依据 DreamFlow `0.38.11` 的图片资产代码，以及当日核对的 [Work Fisher API 文档](https://api.work-fisher.com/docs/)和[机器可读文档](https://api.work-fisher.com/docs/llms.txt)。正式编码前复核服务商接口与计费说明。
>
> 本文件只规划图片资产生图；不会替代现有 `dreamina` 视频生成引擎，也不代表已经调用过付费接口。

## 1. 目标与已确定的选择

在**素材库的图片资产详情**和**分镜中已绑定图片的预览弹窗**提供同一项“GPT 生图”能力。生成提示词取自该图片资产的“文生图提示词”文本框；音频资产不显示入口。无图的图片资产也可以生成，生成成功后补齐图片。

| 项目 | 本方案采用的值 | 原因 |
| --- | --- | --- |
| 服务商模型 | `workfisher-image-g-v2.5-flare` 官方版 | 用户已选定；服务商将其列为适合日常文生图的 Image G v2.5 模型。 |
| 首版生成模式 | 纯文本生图，不发送资产现有图片作为参考图 | 当前需求只指定资产提示词；参考图编辑留作后续独立功能。 |
| 单次参数 | `n=1`、`resolution=1k`、`output_format=png`、`quality=auto` | 限制一次操作的结果数量；其余取服务商默认值，避免隐含比例与风格决定。 |
| 生成结果 | 先看原图与新图，再由用户确认是否采用 | 资产可能被多个分镜共用，结果不能直接覆盖原图。 |
| API Key | 桌面版设置中录入并加密保存；网页版使用启动环境变量 | 密钥不进入前端持久存储、仓库或安装包。 |
| 首版范围 | 单张图片、单任务、单资产确认；不做批量生图或多图挑选 | 把付费提交、结果保存和资产替换流程先做可靠。 |

界面沿用用户口中的“GPT 生图”，技术接入名称以服务商文档中的 **Image G v2.5 Flare** 为准。[模型和参数说明](https://api.work-fisher.com/docs/#image-g-v25)

## 2. 现有项目中的落点

- `app/app.js` 的 `openAssetSettings(asset)` 已展示图片预览与 `#asPrompt` 文本框；只有点“保存”才会调用 `Api.updateAsset` 保存提示词。
- `openBoundAsset(sb, role, assetId)` 是分镜已绑定素材的预览弹窗，目前没有提示词文本框。它的“更换文件”会改变素材库中的同一资产，所有引用它的分镜都跟着更新；“替换素材”只改变当前分镜的绑定。
- `server/services.js` 的资产记录是**项目级**的，包含可选 `prompt`，现有上限为 10000 字符。资产文件位于当前项目的数据目录中。
- `app/api.js` 负责前端请求，`server/routes.js` 负责本地 API；桌面版由 `desktop/main.js` 嵌入同一个 Node 服务。服务端、桌面端不得把外部 API Key 回传给页面。

因此两个弹窗应复用一套图片生成区，并始终按**资产 ID + 项目作用域**获取最新资产记录。分镜快照只有图片、名称等简要字段，不应作为提示词来源。

## 3. 使用者操作流程（功能完成后）

### 3.1 首次配置

1. 登录 Work Fisher 控制台，在 [API 令牌页面](https://api.work-fisher.com/keys)创建密钥，确认账户可用余额和服务商当前价格。
2. 打开 DreamFlow 桌面版 →“项目设置”→“图片生成服务”，粘贴 API Key，点击“保存”。页面只显示“已配置”，不回显原密钥；可更换或删除。
3. 若使用网页版，由启动者在本机设置 `WORK_FISHER_API_KEY` 后启动服务；网页中显示“已由运行环境配置”，不提供密钥编辑框。
4. “已保存”只表示密钥已保管，不代表服务商鉴权或余额已验证。首次提交若返回鉴权或余额错误，页面给出可操作的提示。

### 3.2 从素材库生图

1. 进入项目资产库，打开“角色 / 场景 / 道具 / 首帧 / 分镜”等任一**图片资产**的详情；原来没有图片的占位资产也适用。
2. 在“文生图提示词”中输入或修改内容。点击“保存提示词并生图”。空文本、全空白文本禁止提交；超出本地上限时明确报错，**不自动截断**。
3. 应用只保存此次提示词，不顺带保存弹窗里尚未确认的名称、类型或本地待上传文件。若已有待上传文件，先要求用户完成或取消该文件选择，避免两张候选图争用预览区。
4. 确认框显示资产名、完整提示词的可展开预览、模型、张数、分辨率，以及“服务商按实际消耗收费”的提示。用户确认后才发起外部任务。
5. 弹窗按顺序显示“已提交 / 排队 / 生成中 / 保存图片 / 待采用”。关闭弹窗不取消远端任务；重新打开同一资产可继续查看。
6. 成功后查看原图和生成图，必要时进入全屏。点击“使用这张图”，应用重新统计该资产被多少分镜引用，显示影响范围；再次确认后采用。也可以点击“放弃结果”，原图保持不变。

### 3.3 从分镜已绑定图片生图

1. 点击分镜中的已绑定图片，进入现有“素材预览”弹窗。
2. 新增的提示词区加载**同一素材库资产的最新 `prompt`**，允许在这里编辑并发起生成；操作状态与素材库入口相同。
3. 采用结果时，提示“将更新素材库里的这张资产，以及所有引用它的分镜”；若只想换当前分镜使用哪张已有资产，继续使用原有“替换素材”按钮。
4. 采用成功后刷新分镜缩略图与项目资产库；资产 ID、类型、图号、分镜绑定保持不变。

### 3.4 失败与再次尝试

| 所见状态 | 使用者操作 |
| --- | --- |
| API Key 未配置 / 无效 | 去设置页配置或更换密钥，之后重新提交。 |
| 余额不足、限流、服务商审核失败 | 阅读服务商返回的简短原因，按原因处理；不会自动再次扣费提交。 |
| 提交超时且没有任务 ID | 显示“提交结果未知”；先到服务商控制台核对，应用**不自动重发**。 |
| 已取得任务 ID，查询暂时失败 | 保留任务 ID，稍后继续查询，不另建任务。 |
| 生成成功，但本地下载失败 | 在结果链接有效期间手动点“重新保存结果”；原资产不变。 |
| 新图不满意 | 放弃候选图，原资产不变；再次生图属于一次新的付费提交。 |

服务商文档说明图片任务是异步的、按实际消耗结算，终态可返回 `data.usage`，结果直链约 24 小时有效。界面只在服务商已结算时显示实际扣费，不写死价格。[任务及用量说明](https://api.work-fisher.com/docs/llms.txt)

## 4. 服务商接口与本地接口设计

### 4.1 Work Fisher 调用顺序

```text
用户确认
  → 后端校验资产、提示词、密钥及是否已有活动任务
  → POST https://api.work-fisher.com/v1/image/generations
  → 持久化返回的 task_id
  → GET /v1/image/generations/{task_id}，约每 3–5 秒查询
  → SUCCESS：立即下载并校验图片，转为本地候选图
  → 用户确认采用：安全替换资产文件与 URL
```

首版请求体示意：

```json
{
  "model": "workfisher-image-g-v2.5-flare",
  "prompt": "这里是该图片资产的文生图提示词",
  "n": 1,
  "resolution": "1k",
  "quality": "auto",
  "output_format": "png"
}
```

鉴权头为 `Authorization: Bearer <API Key>`。提交接口返回任务 ID；查询接口给出状态、失败原因或结果 URL。开发时按照真实响应兼容 `id` / `task_id` 的提交字段，并以查询响应的 `data.result_url` 为主要结果来源；缺字段时报告协议错误，不猜测下载地址。`/v1/image/generations` 中的 `image` 是单数。[提交接口](https://api.work-fisher.com/docs/#create-image)、[查询接口](https://api.work-fisher.com/docs/#get-image)

### 4.2 DreamFlow 本地 API 草案

以下为**拟新增**接口，名称和字段在编码时以现有 `/api/v1` 路由风格最终确定；所有资产接口均校验 `projectId`，不允许跨项目读取或采用任务。

| 方法与路径（`/api/v1` 下） | 用途 | 要点 |
| --- | --- | --- |
| `GET /system/image-provider` | 获取服务配置状态 | 只返回 `configured`、能力与错误状态，不返回密钥。 |
| `GET /assets/:id` | 取资产最新信息 | 供分镜预览获取当前提示词；仅当前项目。 |
| `POST /assets/:id/image-jobs` | 保存提示词快照并提交任务 | 请求包含 `prompt`；检查重复任务，响应本地 `jobId`。 |
| `GET /assets/:id/image-jobs/current` | 获取运行中或待采用任务 | 返回状态、提示词快照、模型、实际扣费（若已结算）。 |
| `GET /assets/:id/image-jobs/:jobId/preview` | 本地候选图预览 | 仅在图片下载并校验后可读；不把服务商直链交给页面。 |
| `POST /assets/:id/image-jobs/:jobId/apply` | 确认采用结果 | 再验资产、项目、任务状态与引用数；保留原资产直到新文件及数据库写入成功。 |
| `DELETE /assets/:id/image-jobs/:jobId` | 放弃本地候选结果 | 清理本地候选文件；已提交的远端任务若无取消接口，不宣称已取消或退款。 |

密钥写入和删除走 `desktop/preload.js` 暴露的**具名 IPC**，由 Electron 主进程调用 `safeStorage`；网页版只读取服务启动环境变量。网页 API 与 IPC 都不得返回原密钥。后端通过 `createServer()` 注入的凭据读取函数取用桌面密钥，保持 `server/` 可以用假凭据单独测试。[Electron safeStorage 文档](https://www.electronjs.org/docs/latest/api/safe-storage)

## 5. 状态、数据与文件安全

### 5.1 任务状态

| 本地状态 | 进入条件 | 接下来允许的动作 |
| --- | --- | --- |
| `submitting` | 用户确认、尚未拿到服务商任务 ID | 等待响应；超时转为 `submission_unknown`。 |
| `queued` / `running` | 已拿到并保存任务 ID | 查询同一任务；关闭弹窗或重启后可恢复。 |
| `saving_result` | 服务商成功，正在下载 | 下载、校验并持久化本地候选图。 |
| `ready` | 本地候选图可用 | 预览、采用或放弃。 |
| `failed` | 服务商失败或明确拒绝 | 展示原因；手动发起新任务。 |
| `submission_unknown` | 提交结果不确定且无任务 ID | 人工核对服务商记录；禁止自动重发。 |
| `applied` / `discarded` | 用户完成处理 | 只保留必要的审计摘要，清理候选文件。 |

“关闭弹窗”不是取消任务。服务退出时停止查询定时器；再次启动后只恢复有 `task_id` 的未结束任务。对查询请求可做有限退避；**提交请求不做自动重试**。同一资产有 `submitting`、`queued`、`running`、`saving_result` 或 `ready` 任务时，入口显示现有任务并阻止再提交。

### 5.2 持久化与采用

1. 在 `db.json` 增加内部 `imageJobs` 集合，记录本地任务 ID、项目 ID、资产 ID、提示词快照、模型、服务商任务 ID、状态、时间、已结算用量和候选文件相对路径；按 `server/schema.js` 的迁移规则升级 schema，并给旧库加空集合。**不记录密钥、鉴权头和带签名参数的远端 URL**。
2. 候选图放在当前项目数据目录的受控子目录，不放安装目录，也不使用系统临时目录。预览走本地授权接口；迁移数据目录时随项目数据一起迁移。
3. 下载只接受服务商结果提供的 HTTPS URL。每次重定向重新检查协议、解析后的公网地址、响应体大小及图片格式；限制下载时间、最大字节数，校验 PNG/JPEG/WebP 文件特征与基本尺寸。拒绝 HTML 错误页和不完整图片。
4. 采用时生成新的带版本文件名，保证浏览器缓存刷新；写完新文件并校验后更新资产 URL 与大小，强制把数据库刷盘成功，最后才清理旧文件。若中途失败，回滚数据库引用并保留原图。所有引用该资产的分镜随后刷新。
5. 资产或项目被删除时清理相应候选文件及本地任务记录；对已经提交的远端任务，只停止本地使用其结果，不承诺远端取消。对遗留候选文件做有界清理，不能删除用户原始素材。

### 5.3 凭据与内容边界

- 桌面版用 Windows 用户级加密能力保存密钥；系统加密不可用时返回错误，不降级为明文配置。允许用户更换、删除密钥。网页模式以 `WORK_FISHER_API_KEY` 环境变量注入，不放在可下载的配置文件或前端构建物中。
- 仅后端向服务商发送提示词。生成按钮明确表示提示词将发给第三方服务；首版不上传原图、其他素材、分镜脚本或用户本地路径。
- 日志只记录本地任务 ID、服务商任务 ID、状态和脱敏错误，不记录密钥、提示词全文、鉴权头或图片直链。
- 保持桌面版现有随机本地端口、Bearer 保护、来源检查和 CSP；外部请求由后端执行，页面不直接连接第三方域名。

## 6. 开发执行顺序

| 阶段 | 具体工作 | 完成标志 |
| --- | --- | --- |
| 0. 基线 | 从最新 `main` 建工作分支；核对资产弹窗、保存逻辑、作用域、迁移与现有测试。 | 工作树干净，记录当前版本及回归命令。 |
| 1. 服务商适配 | 新建只用 Node 内置模块的 Work Fisher 客户端；注入 HTTP 传输和凭据；解析提交、查询、用量与错误。 | 假传输覆盖成功、失败、401、402、429、超时及缺字段。 |
| 2. 任务与文件 | 增加 schema 迁移、任务状态机、恢复查询、安全下载、候选预览、采用与清理；路由校验项目作用域。 | 重启后续查同一任务；失败不损坏原素材；重复点击不产生第二次提交。 |
| 3. 密钥配置 | 桌面主进程加密存储、具名 IPC 和设置状态；网页版读取环境变量。 | 页面和日志无法读回密钥；删除密钥后不能再提交。 |
| 4. 两处界面 | 复用生图组件，接上提示词保存、确认、进度、结果对比、影响范围提示与刷新。 | 素材库与分镜预览行为一致；音频入口隐藏。 |
| 5. 文档与版本 | 更新接口说明、项目文档、变更记录和必要的架构记录；重建 `dist/`；新增能力按 MINOR 升版。 | 文档明确实际行为，构建产物与源码同步。 |
| 6. 验收与交付 | 完成下节验证，提交并推送 `main`；是否制作安装包按单独发版流程决定。 | 自动化全绿、桌面交互通过，遗留限制记录清楚。 |

## 7. 验收清单

### 自动化与隔离

- 服务商适配测试使用**假的传输层**，不接真实密钥、不产生费用；验证准确的单数路径、Bearer 请求头、Flare 请求体、状态解析及 `data.usage`。
- 路由与任务测试覆盖跨项目访问、无图资产、空提示词、长提示词、重复提交、提交超时、查询重试、重启恢复、资产删除、候选图清理。
- 文件测试覆盖 HTTPS 重定向到内网、异常 Content-Type、HTML 假图片、过大/截断图片、保存失败、数据库刷盘失败及原图回滚。
- 执行 `node build.js`、`npm run verify`、`npm run smoke:web`、`npm run e2e`；测试数据始终使用仓库内隔离数据目录，绝不写入 `server/data/` 或真实用户数据目录。

### 手工界面

- 在桌面版素材库详情和分镜绑定图片预览分别走通“输入提示词 → 确认 → 查看进度 → 对比 → 采用／放弃”。
- 核对有原图、无图、同一资产被多分镜引用、正在生成时关闭并重开弹窗、断网后恢复、删除密钥后的状态。
- 检查居中窗口、480px 抽屉、窄窗口及浅色／深色主题；按钮、提示词、进度与对比图不遮挡、不溢出。
- 使用真实 API Key 的**一次付费验收**单独进行：事先确认费用和授权，成功后验证图片已经落在项目数据目录，关闭应用再打开仍可查看。自动化流水线不进行这一步。

## 8. 完成判据与本期边界

完成判据：两处入口都取同一资产的最新提示词；同一任务不会因双击或重启被重复提交；成功结果及时保存到本地；采用前可比较并确认影响范围；采用失败仍能打开原图；密钥不出现在页面响应、日志或仓库中；回归命令通过。

首版只提供**文本生一张图**。参考图编辑、批量生图、多模型切换、多个候选图、自动采用、远端任务取消、准确的提交前价格预估均留待后续单独设计。服务商价格与可用模型可能调整，以其控制台和最新文档为准。
