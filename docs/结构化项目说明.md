# DreamFlow · 结构化项目说明

## 一、项目目标与功能范围

**一句话**：面向 AI 短剧 / 分镜视频生产的**分镜批量管理工作台**。本地单机运行，通过即梦官方「创作 CLI（`dreamina`）」完成**真实**视频生成，全链路**零演示数据、零内置二进制**。

**仓库名 / 产物名**：`DreamFlow`（安装包 `DreamFlow-<版本>-x64-Setup.exe`，主程序 `DreamFlow.exe`）。
**中文产品名**：即梦批量生成控制台（界面、托盘、快捷方式）。
**两处刻意保留旧名 `JimengConsole`**：`appId`（决定 Windows 能否原地升级）与数据目录 `%USERPROFILE%\Videos\JimengConsole\`。

### 功能范围

| 层 | 能力 |
|---|---|
| 组织 | Project（项目）→ Workspace（代码名，界面叫「分镜表」）→ Storyboard（分镜）；Asset（素材）属于**项目**，同项目内所有分镜表共享一份素材库 |
| 分镜 | 批量导入提示词（`;;` 分隔）、创建 / 编辑 / 排序、批量改时长、按提示词标注重算时长、干跑、批量提交 / 取消 / 重试 / 删除、参考素材绑定与按名自动匹配 |
| 素材 | 上传 / 建元数据 / 重命名 / 换文件 / 删除 / 提示词文本导入；类型 = 角色 / 场景 / 道具 / 首帧 / 参考图 / 音频 |
| 生成 | 唯一引擎 = `dreamina` 创作 CLI；`text2video` / `multimodal2video`；图片 + 视频 + 音频混合参考；图号表（`asset-lock.js`，提示词里写 `@图片N`） |
| 记录 | 追加式快照（generate / dryrun × succeeded / failed / canceled / previewed）；分镜被删记录仍在；导出 md / csv / json |
| 设置 | 项目级：分隔符、生成参数默认值；系统级：队列并发、自动重试 |
| 系统 | CLI 检测 / 安装 / 更新（官方 CDN）、CLI 登录 / 切换账号、适配器状态、数据目录查询与迁移 |
| 桌面端独有能力 | 单实例、托盘常驻、应用内自更新、旧数据导入、外部工具自动定位 |

### 两种交付形态（共用同一份前端与后端业务代码）

| | 网页版 | 桌面版（Electron） |
|---|---|---|
| 启动 | `node server/index.js` | 双击 exe，主进程自启内嵌服务 |
| 端口 | 固定 `8787` | 随机端口（被占用也能起） |
| 鉴权 | 默认无，可设 `JC_TOKEN` | 每次启动生成一次性 Token |
| 数据根 | `server/data/`（仓库内） | `%USERPROFILE%\Videos\JimengConsole\`（仓库外） |
| 配置 / 日志 | `server/config.json` / 终端 | `%APPDATA%\即梦批量生成控制台\` |

### 明确不做（边界）

- 无用户体系、无分页、无虚拟滚动、无登录流程（接口签名已按契约预留）。
- 无多端同步：素材图号表、生成记录、积分余额提醒均为本地单机语义。
- **不内置** `dreamina` 二进制（再分发授权未确认，运行时从官方 CDN 下载）、**不内置** ffmpeg / ffprobe（可选依赖，缺失只影响封面与音频时长）。
- `dreamina-canvas`（画布 CLI）已于 2026-09-18 彻底移除，模型注册表里仅保留历史名的迁移映射。

## 五、核心数据流与关键调用链

### 5.1 启动链

```
网页版：server/index.js → loadConfig() → createServer({config})
桌面版：desktop/main.js → runtime.configure({mode,dataDir,logsDir,configPath})
        → loadConfig(overrides:{port:0, token:随机, host:'127.0.0.1'}) → createServer

createServer:
  makeDreaminaAdapter(cfg) → makeWorker(cfg,{dreamina}) → makeRouter(cfg,worker)
start():
  store.load()                       // 读库 → 损坏恢复链 → 空库/迁移
  worker.reconcileOrphans(db)        // 重启后停在 generating 的 → failed(INTERRUPTED)
  cliJobs.gc(db)                     // 孤儿清、终态按龄淘汰、活跃保留
  setInterval(tick, 800ms)           // 队列调度
  listen(port, host)
  → 300ms 后后台探测 CLI（预热缓存）
  → 1200ms 后 backfillCovers（补历史产物封面）
```

### 5.2 请求链

```
HTTP 请求
 → originPolicy(req,cfg)      // 同源放行；仅本地 Origin 回 ACAO；Origin:null 由 allowFileOrigin 决定
 → Bearer 校验（cfg.token 非空时；仅对 /api/v1）
 → 分流：/ 首页（现生成 CSP nonce，注入 APP_CONFIG.token）
        /app/ /dist/  → paths.resolveStaticPath（白名单根 + contained）
        /files/ /media/assets/ → paths.resolveServePath（逐段白名单 + contained）
        /api/v1/*     → dispatch(req,res,sub)
 → dispatch: store.load() → scopeIdsOf(pathname,query) → 逐条匹配 [method, regex, handler]
 → handler → scopeOf(ctx) → projects.resolveScope（父子关系校验，不符 404）
 → services.<fn>(db, body, adapter, scope) → ok(res,data)
 → 异常统一 fail(res, err) → { code, message, data.__err, traceId }
```

### 5.3 生成链（最核心，改动前必读）

```
前端：Api.batchSubmit(ids, concurrency, dryRun)
      Idempotency-Key = 提交内容 + 2 秒时间桶（吸收连点，防重复扣费）
 ↓
routes: POST /storyboards/batch-submit → withIdempotency（键 = 路径 + 作用域 + 客户端键）
 ↓
services.batchSubmit
  可用性闸：D.peek() / D.lastProbe() 优先；从未探测过才限时等一次（≤2.5s）
  —— 刻意不强制探测：`dreamina user_credit` 实测 8~9 秒，放到提交路径会变成"点提交卡 9 秒"
  不可用 → cliUnavailableError：installed=false→51101 / 装了没登录→51102 / 兜底 51001
 ↓
services.doSubmit
  逐条校验：存在 → 同工作区（跨项目拒绝）→ 非运行中 → 非积分不足
  TS.assertTransition(status → queued)；分配新 attemptId（旧一轮的迟到结果从此失效）
 ↓ store.save()
worker.tick（每 800ms）
  并发闸：effConc = min(settings.queue.concurrency, maxConcurrencySafety>0 ? 上限 : ∞)
  取 queued 按 seq 排序，补空位 → runOne
 ↓
worker.runOne
  guard(db,sb,attemptId,GENERATING)   // deleted / workspace-deleted / stale-attempt / illegal 一律拒写
  模型可用性校验（models.dreaminaModelOf）
  干跑（cfg.dryRun 或 sb.submitDryRun）→ buildSubmitArgs → finishDryRun（回到 draft，落 dryrun 记录）
  否则 → runViaDreamina
 ↓
worker.runViaDreamina
  D.probe() → 积分提醒（低于 creditWarnBelow 写 sb.creditWarning + 日志）
  ★ 派发前先落 cliJobs（state=submitting）—— submit_id 是事后续查的唯一凭据
  D.runVideo(db, sb, {log, progress})
      → buildSubmitArgs(sb, db)   // models.limitsFor 截断参考图；asset-lock 组装 @图片N 区块；只补不改原文
      → spawn dreamina text2video|multimodal2video --model_version ... --image ... --poll N
      → 解析 gen_status（success / fail / querying）；成功判定不看退出码
  guard → 失败 mapTaskError（可自动重试：51004/51005 且 retryCount < maxRetry，换 attemptId）
  D.downloadResult(db, sb, submitId) → --download_dir → pickArtifact / pickCover
  D.makeCover（ffmpeg 抽帧，缺 ffmpeg 静默跳过并给出 coverNotice）
  guard 再验一次 → succeeded → REC.append（快照）→ store.save()
```

### 5.4 状态机与写入守卫（`server/task-state.js`）

```
draft → queued → generating → succeeded / failed / canceled
                     └→ draft（干跑回退）
failed / canceled → queued（retry）      succeeded → queued（重新提交）
```
- 守卫三种拒绝：`deleted`（分镜已删）、`stale-attempt`（attemptId 已变）、`illegal`（状态机不允许）。
- 被拒时**不写该分镜日志**（那正是幽灵数据本身），改写系统日志；若已拿到 `submit_id`，先记进系统日志再丢弃（钱已花，凭据不能丢）。
- 重试只允许 `failed` / `canceled`（queued/generating 重试会重复扣费）。

### 5.5 持久化链（`server/store.js` + `schema.js`）

```
store.save()（节流）→ saveNow()：序列化 → 临时文件 → rename（原子）→ 备份轮转 db.json.bak-*
load()：读 db.json
        失败 → quarantine 成 .corrupt-<时间>（保留证据）
             → 依次尝试 db.json.bak-*（新→旧）→ backup/pre-schema-v<N>-*.json
             → 全部失败才空库（且必须明确提示）
        → schema.runMigrations（在克隆体上跑，全成功才"清键 + 赋值"写回原对象；失败则拒绝写盘让服务起不来）
```

### 5.6 前端数据流

```
Api（api.js，唯一拼 URL 处）→ 数据在 app.js 的 S 状态 → render* → DOM
作用域：Api.CFG.projectId / workspaceId（**只有前端**能有"当前"概念；后端一律 request-scoped）
每个业务请求显式带 projectId / workspaceId → 后端 resolveScope 校验父子关系
错误：ApiError(code, message, data, traceId) → ERR_TEXT 兜底文案 → Toast；工具类码（511xx）给"去处理"入口
```

### 5.7 自更新链（`desktop/updater.js`）

```
latest.yml（GitHub Release）→ 版本比较 → 下载（边下边算 sha512）
→ 校验不过即丢弃（绝不交给安装器）
→ 调起 NSIS：/S --updated --force-run（三者缺一不可）
→ updater-transport 走系统代理；跨域重定向丢弃 Authorization
```

### 配置优先级

`loadConfig(overrides)` > 环境变量 > `server/config.json` > 内置默认。
配置**只在进程内加载一次并复用**（`runtime.setCurrentConfig`），否则桌面版的随机端口 / Token 会被默认值悄悄盖掉。

## 七、代码风格与约定

### 分层（不要跨层写）

| 层 | 文件 | 只做 |
|---|---|---|
| 接口 | `app/api.js` | 请求 → 数据 / `ApiError`，**不碰 DOM、不拼业务 URL 之外的东西** |
| 视图 | `app/app.js` | 数据 → DOM 与用户操作，**不拼 URL** |
| 路由 | `server/routes.js` | 匹配 + 作用域 + 幂等，**不写业务** |
| 业务 | `server/services.js` / `records-layer.js` | 校验 + 编排 |
| 作用域 | `server/projects.js` | `resolveScope`，**不导出任何 current/setCurrent** |
| 队列 | `server/worker.js` | 派发与收尾 |
| 引擎 | `server/dreamina-cli.js` | CLI 进程与协议 |
| 持久化 | `server/store.js` + `schema.js` | 原子写与迁移 |

### 「唯一事实来源」清单（改动前先看这里，别在别处复制一份）

| 事实 | 文件 |
|---|---|
| 运行模式 / 数据根 / 生效配置 | `server/runtime.js` |
| 磁盘布局与资源 URL 形状 | `server/paths.js` |
| 桌面版目录布局 | `desktop/runtime-paths.js` |
| 模型名称归一 / 能力边界 / 上限系列 | `server/models.js` |

| 素材图号与提示词绑定区块 | `server/asset-lock.js` |
| 作用域解析 | `server/projects.js` |
| 错误码与元数据 | `server/util.js`（前端 `app/api.js` 严格对齐） |

### 命名

- ID 前缀：`pj_` 项目、`ws_` 工作区、`st_` 分镜、`as_` 素材、`rc_` 记录、`at_` 派发轮次；形状统一 `<前缀>_<字母数字>`，白名单 `ID_RE`。
- 后端文件：小写单词（`store.js`、`dreamina-cli.js`）；导出：`makeXxx`（工厂）、`resolveXxx`（解析）、`findXxx`（查找，不存在返回 null）。
- 错误码：`4xxxx` 通用（40001/40100/40300/40400/40900/42900/50000），`510xx` 上游与 CLI 运行期，`511xx` 外部工具缺失/未登录。
- 注释：中文，且解释「**为什么**」，不是「这行在做什么」。仓库里大量**事故注释**（记录踩过的坑），**不许删** —— 那是防止第二次踩坑的唯一记录。

### 错误处理

- 统一信封 `{ code, message, data, traceId }`；`code !== 0` 即业务失败；`fail()` **一律回 HTTP 200**（码在 body 里）。
- `ApiError(code, message, data)` 抛出，路由层统一 `fail()` 兜住。
- `errInfo(code)` 返回四件套 `{ name, category, retryable, http, hint }`，经 `data.__err` 下发（`message` 是具体原因、`messageHint` 是通用建议，两者并列展示）。
- 可选依赖（ffmpeg / ffprobe）失败一律**静默降级**，但必须能通过 `ffprobeStatus()` / `ffmpegStatus()` 说清原因（missing vs failed）。

### 安全约定

- 路径：id / 文件名**逐段白名单** + `contained()` 目录包含性检查（必须比 `base + sep` 前缀，否则 `output-bak` 会被误判在范围内）。
- CSP：`script-src 'self' 'nonce-<每响应现生成>'`，`style-src` 保留 `unsafe-inline`；`frame-ancestors 'none'`。
- CORS：只对本地 Origin 回 ACAO；非本地一律拒绝并在 API 上直接挡。
- 幂等键必须含**作用域**，否则跨项目会回放别的项目的响应。
- 令牌：只进不出（状态接口只回 `hasToken`），跨域重定向丢弃 `Authorization`。

### 收尾清单（Definition of Done）

1. 改了 `app/` → `node build.js`（脚本自带 `$$` / script 块 / 外部引用四道校验）。
2. **真跑一遍**：`npm run verify` 全绿只是入场券；改 UI 就 `npm start` 或跑 `smoke:web` / `e2e`；改后端就发真实请求。
3. 版本号同步**两处三地**：`package.json`（唯一生效来源）+ README「当前版本」+ README「变更记录」。
4. 在 `docs/CHANGELOG.md` 写清「为什么改 + 踩过什么坑」。
5. 同步受影响文档（改接口 → 前端对接说明；改架构 → `docs/更改文档.md`；改本清单 → `docs/项目文档.md` §9）。
6. 提交并推送；发版另见 `docs/版本发布与更新流程.md`（tag 必须单独 push；安装包只走 GitHub Releases）。

### 红线（违反造成不可恢复损失）

不提交 `server/data/` 与 `release/`；不删 `build/icon-source.png` / `icon.png` / `icon.ico`；不删用户的 `db.json` 或 `projects/`；不在应用里嵌 GitHub 令牌；不往安装目录写数据；不用真实数据做测试。
