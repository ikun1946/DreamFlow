# DreamFlow · 即梦批量生成控制台

> **项目英文名：DreamFlow** —— 它同时是 GitHub 仓库名，所以 `git clone` 下来的文件夹名也是 `DreamFlow/`。
> 中文产品名仍是「即梦批量生成控制台」：界面标题、托盘、快捷方式显示的都是这个中文名。
>
> 安装包与可执行文件在 **0.32.0 完成更名**：产物名 `DreamFlow-<版本>-x64-Setup.exe`、主程序 `DreamFlow.exe`。
> 更名前是 `JimengConsole-*` —— 那一步刻意延后，因为旧版更新器的白名单只认 `JimengConsole-`，
> 直接改名会让老用户「看得到更新却装不上」。两步走的完整理由见 [CHANGELOG 0.31.0 / 0.32.0](docs/CHANGELOG.md)。
>
> ⚠ 有两处**仍叫 `JimengConsole`**，且是刻意保留的：**应用 ID**（`appId`，决定 Windows 能否认出
> 「同一个应用」、能否原地升级）与**数据目录**（`%USERPROFILE%\Videos\JimengConsole\` —— 改名会让
> 用户以为项目全没了）。这两处界面上都看不到。

面向 AI 短剧 / 分镜视频生产的**前后端完整项目**：前端是分镜批量管理工作台，后端是本地桥接服务，通过即梦官方**创作 CLI（`dreamina`）**完成真实视频生成。**无任何演示/模拟数据**——所有数据来自真实数据流。

> ⚠ 2026-09-18：**画布 CLI（`dreamina-canvas`）已彻底移除**，本项目只使用创作 CLI 一个生成引擎；历史上曾依赖画布 CLI 的能力（画布节点引用、报价→确认的积分安全阀）随之下线，积分改为"提交前余额提醒"（`creditWarnBelow`）。

> 📖 完整变更记录见 **[docs/CHANGELOG.md](docs/CHANGELOG.md)**（0.29.0 → 最新）。README 只放**入门**；老用户查变更 / 想看历史踩坑请走 CHANGELOG。

## Windows 桌面版

网页版是"手动起服务 + 浏览器打开"；桌面版把这条链路收进一个窗口里：**内嵌服务由主进程启停，页面由同一个服务托管**（同源，视频 Range 与轮询都不用改）。前端源码是同一份 `app/`，两边共用。

### 跑起来 / 打包

```bash
npm install                   # 只为桌面端装 electron 与 electron-builder
npm start                     # 开发态直接起桌面窗口
npm run dist                  # 打 NSIS 安装包 → release/JimengConsole-<版本>-x64-Setup.exe
npm run pack                  # 只出免安装目录 → release/win-unpacked/（排障时更快）
npm run icons                 # 重新生成图标：build/icon.png、build/icon.ico、app/icon.png
```

安装包约 106 MB（Electron 运行时占绝大部分）。**不携带 dreamina / ffmpeg**：创作 CLI 可以在应用内一键安装（见下节），ffmpeg 需自行安装（只影响封面抽帧与音频时长，不影响生成）。

### 数据放在哪

桌面版**不往安装目录写任何东西**（装到 Program Files 后那里是只读的），两个位置分开：

| 位置 | 放什么 | 为什么在这 |
|---|---|---|
| `%APPDATA%\即梦批量生成控制台\` | `desktop-config.json`、`desktop-state.json`（窗口尺寸）、`logs\main.log` | 配置与日志体积小，跟着用户走没负担 |
| `%USERPROFILE%\Videos\JimengConsole\` | `db.json`、`backup\`、`projects\<项目>\{assets,output}\` | **视频动辄几个 GB**，不能放会被云同步拖走的漫游目录 |

数据根可以用 `JC_DATA_DIR` 环境变量覆盖（换盘、或者把库放到别的机器上）。

### 和网页版的行为差异

- **随机端口 + 一次性 Token**：不再抢 `8787`，端口被占也能启动。Token 每次启动重新生成、只在本进程内存里，用来挡住"本机其它网页偷偷调用生成接口"（那些接口会真扣积分）。仅监听 `127.0.0.1`。
- **单实例**：第二次启动不会开出第二个服务，而是把已有窗口顶到前面。
- **托盘常驻**：窗口关闭时若还有任务在跑，会收进托盘并弹气泡提示，而不是直接掐断本地跟踪。托盘菜单可看运行中任务数、打开数据/日志目录、跑环境检测、导入旧数据。
- **外部工具自动定位**：`dreamina` / `ffmpeg` / `ffprobe` 按「显式配置 → 随包 `resources\bin\` → PATH → 常见安装位置（WinGet、`C:\ffmpeg\bin` 等）」查找，缺失时只影响对应功能，不会让应用起不来。
- **退出一定走优雅停止**：先停轮询、再收 dreamina 子进程（Windows 下用 `taskkill /T /F` 收整棵进程树）、落盘、最后关服务，不留孤儿进程。

### 创作 CLI 的安装与更新（应用内一键完成）

**没装过即梦创作 CLI 也能用**：设置抽屉里点一下「安装创作 CLI」即可，不需要 Git Bash，也不需要手动跑命令。

为什么必须由应用代劳：官方只提供一种安装方式 —— `curl -s https://jimeng.jianying.com/cli | bash`，而那个脚本的 Windows 分支要求 MINGW / MSYS / CYGWIN（即 Git Bash）。**干净的 Windows 电脑跑不了它**，所以"让用户自己去装"这条路本来就不通。

三条设计取舍（改之前请先读 `server/cli-installer.js` 顶部的块注释）：

1. **运行时从官方 CDN 下载，不把二进制打进安装包。** 打包分发别人的二进制属于"再分发"，而 dreamina 的再分发授权至今未确认（见「已知边界」）。运行时下载不改变分发主体 —— 用户从官方源拿，应用只是搬运。
2. **装到官方脚本用的默认位置**（`%USERPROFILE%\bin\dreamina.exe`）。这样手工装的、应用装的、官方脚本装的是**同一个文件**，不会出现"三份 CLI 互相不知道"。
3. **更新就地替换但先备份**（`.bak-<时间>`），并且校验下载到的是**合法 PE** —— CDN 出问题返回一个 HTML 错误页时，不会把用户原本能用的 CLI 覆盖掉。

CLI 状态在界面上分**三态**显示，因为用户要做的动作完全不同：

| 状态 | 界面显示 | 该做什么 |
|---|---|---|
| 未安装 | 明确写「未安装」 | 点「安装创作 CLI」 |
| 已安装未登录 | 「已安装，但未登录」 | 点「创作 CLI 登录」 |
| 就绪 | 显示账号与积分 | 正常生成 |

**顺带修掉一个会把人引错方向的缺陷**：以前"版本号"读的是 `~/.dreamina_cli/version.json`，那是**上次安装脚本写下的**，跟实际在跑的 exe 没有任何绑定关系。后果是：exe 根本不存在时它照样报「已安装但未登录」（用户会去查登录，而真正的问题是 CLI 不在）；反过来 exe 正常但那个文件缺失时，一个完全可用的 CLI 又被判成"不可用"。现在改成问 **exe 自己**（`dreamina version` 返回 commit 与构建时间），"官方最新版"则单独从官方 CDN 的 `version.json` 取，两者不再混用。

### 应用内更新

桌面版可以在应用内完成更新：**检查 → 下载 → 校验 → 静默安装 → 自动重启**。不需要手动去下载安装包。

入口有两处：**设置抽屉 → 应用更新**，以及**托盘菜单 → 检查更新…**。

为什么没用 `electron-updater`：自更新真正需要的只有三件事 —— 知道"最新版是多少"、下载、调起安装器。而 electron-builder 生成的 NSIS 安装器**本来就支持**这三个开关（依据是 `NsisTarget.js` 里的 `flags(["updated","force-run",...])`）：

| 开关 | 作用 |
|---|---|
| `/S` | 静默安装，不弹界面 |
| `--updated` | 标记为升级 —— 安装脚本明确用它保证**用户数据不被删** |
| `--force-run` | 装完自动重启应用（辅助式安装器只在"静默 + force-run"时才重启） |

本仓库坚持零运行时依赖，为一个已经具备的能力再引一个运行时依赖不划算。实现见 `desktop/updater.js`。

**更新源可配三种**（设置 → 应用更新 → 更新源设置）：

| 更新源 | 适用场景 | 需要令牌 |
|---|---|---|
| GitHub Releases | 默认。本仓库**已公开**（2026-09-21 起），匿名即可读取 release，**无需令牌**；仅私有库才需要 | 否（私有库需） |
| 自定义 URL | 以后把安装包放到公开 CDN / 自建静态站 —— 那时就不需要令牌了 | 否 |
| 本地目录 | 离线、内网，或者"我刚打完包，让装好的应用直接升级" | 否 |

令牌建议用**细粒度 PAT**：只勾这一个仓库的 `Contents: Read` 就够了。它只存在本机配置文件（`%APPDATA%\即梦批量生成控制台\desktop-config.json`）里，**不会进安装包** —— 安装包是可解压的，把令牌打进去等于把仓库访问权交出去。

安全上做了四道闸：

1. **只接受 https**（本地目录模式除外）—— 更新源是可配的，不能让它变成降级攻击面
2. **下载完校验 sha512**（`latest.yml` 里带着 electron-builder 生成的哈希），边下边算，不额外读一遍磁盘
3. **校验不通过就丢弃并拒绝执行**，临时文件一并清掉
4. **跨域重定向时丢掉 Authorization 头**（GitHub 的附件下载会 302 到对象存储，把令牌带过去等于交给第三方主机）

### 旧数据导入

桌面版的数据根和网页版的 `server/data/` 不是同一个目录，所以首次启动会**自动检测**旧库并询问是否导入（检测到且新库为空时才问，不重复打扰）。之后随时可以从托盘菜单「从旧版导入数据…」手动选目录。

导入是**复制**，不是搬家：旧目录原样保留；目标已有库时会先备份到 `backup/pre-import-<时间戳>/`。导入后会输出一份报告 —— 项目 / 分镜表 / 分镜 / 素材 / 生成记录 / 视频文件各多少个，以及**库里引用的文件有没有全部找到**（有缺失会逐条列出，这是判断"丢没丢东西"的唯一依据）。

## 真实生成链路

1. 导入 / 新建分镜（`queued`）→ 勾选后「提交所选」（`batch-submit`，提交前确认创作 CLI 可用，未连接返回 `51001`）；
2. 后端队列按并发数派发 worker：**派发前先把任务落库**，再由创作 CLI 适配层组装并执行 `dreamina text2video` / `multimodal2video`；
3. 任务在即梦侧为异步：拿到 `submit_id` 后轮询 `query_result` 至 `gen_status` 终态；`fail` 映射为 `51002`、审核拒绝 → `51003`；
4. 完成：产物下载校验后由 `/files/` 提供 `videoUrl`；本地跟踪中断（重启）时由启动清理把分镜标为失败并保留 `submit_id` 供续查；
5. 前端 3–10s 退避轮询 `GET /storyboards/progress`（只回有变化的行）。

> **账号要求**：真实生成需要已开通相应权限的即梦账号（实测非会员账号会被服务端闸门拒绝，任务以 `40300` 给出明确原因；接口联通、错误处理、恢复协议均已按真实链路落地）。

## 前端核心机制

- **轮询退避**：基线 3s，连续 3 次无变化 → 6s → 10s 封顶；异常指数退避封顶 30s；页面隐藏暂停、恢复即拉；全部终态停止。
- **乐观更新 + 回滚**：改时长立即生效（300ms 合并提交），失败回滚 + Toast；批量提交 `accepted[]` 乐观置队。
- **快速多选**（素材面板与分镜列表共用一套）：区域内**按住拖拽框选**（`Ctrl`/`Shift` 追加、`Alt` 减去，实时高亮并显示命中数）、**区间选择**（填起止序号，越界自动收敛并提示）、**全选 / 反选 / 清空**，已选数量实时显示。拖拽期间只改 class 不重绘列表 —— 416 行下实测 0.12ms/帧；起拖超过 4px 才拦截 click，普通点击仍照常打开卡片编辑弹窗。
- **四态齐全**：骨架屏 / 空态（含「批量导入」引导）/ 错误态（带重试）/ 降级。
- **枚举不硬编码**：模型 / 画幅 / 分辨率 / 时长边界全部来自 `GET /meta/options`（后端合并静态配置与 CLI 实时模型目录）。
- **时长控件**：步进器、双击直接输入、预设下拉；已完成分镜由服务端 `canEditDuration` 锁定。

## 备份运行数据（git 替代不了的那部分）

`server/data/` 被 `.gitignore` 排除，**远端仓库里没有它**。而其中的内容丢了就没了：

| 内容 | 为什么 git 保不住 |
|---|---|
| `db.json` | 分镜 / 素材 / 生成记录，手工重建代价极大 |
| `output/` 视频产物 | 真实生成、**花过即梦积分**，不可再生成 |
| `assets/` 素材图 | `DELETE /assets/{id}` 会连磁盘文件一起删且不留痕（见「已知边界」第 1 条） |

所以**代码靠 git、数据靠这个脚本**，两者互不替代：

```bash
bash scripts/backup-data.sh                       # 备份到 $HOME/dreamflow-backups/<时间戳>/
JC_BACKUP_ROOT=/d/backups bash scripts/backup-data.sh   # 换目标位置（建议放到移动硬盘等另一块盘）
JC_BACKUP_KEEP=5 bash scripts/backup-data.sh      # 只保留最近 5 份（默认 10）
```

每次运行产生一个独立快照目录，不覆盖历史；脚本会逐类比对文件数、不一致就报错退出，并在快照里写一份 `MANIFEST.txt`（记录**这份数据对应哪一版代码**、各项校验和、恢复步骤）。两道防护：拒绝把备份写进项目目录内部（否则一次误删项目会把它一起带走）、数据目录为空时拒绝产出一份空备份。

> ⚠ 恢复时先停掉 `node server/index.js`，否则运行中的服务会把覆盖回去的数据再写一遍。

## 多项目架构与数据隔离

**层级**：`Project`（项目）→ `Workspace`（代码里的名字，**UI 上叫「分镜表」**）→ `Storyboard`（分镜）。
`Asset`（素材）属于**项目**，因此同一项目下的所有分镜表天然共享一份素材库。

> 术语说明：早期界面把 Workspace 叫「页面」，但它容易与「网页 / 分页页码」混淆，
> 已按用户要求统一改称**分镜表** —— 一张分镜表就是一组分镜的容器。
> 代码里仍是 `workspace` / `ws_` 前缀，接口路径也不变。

**四条不可违反的规则**（实现与测试都以此为准）：

| 规则 | 落地位置 |
|---|---|
| Project 是数据隔离边界 | 所有查询按作用域过滤；跨项目读写一律 404 |
| Workspace 是分镜容器 | 分镜归属 `workspaceId`，序号也按工作区独立编号 |
| Asset 属于 Project，不属于 Workspace | 素材只有 `projectId`，**刻意不加** `workspaceId` |
| 后端不存在「当前项目」全局变量 | 作用域一律 request-scoped，由 `projects.resolveScope()` 统一解析并校验 |

**作用域怎么传**：三种路径形态都支持，作用域优先级为「路径 > 查询串 > 旧式扁平兜底」。

```
/workspaces/ws_x/storyboards     工作区作用域（推荐）
/projects/pj_x/storyboards       项目作用域 → 落到该项目的 defaultWorkspaceId
/storyboards?workspaceId=ws_x    旧式扁平路径 + 查询串
/assets?projectId=pj_x           素材按项目（这正是"后端按 projectId 查询"的入口）
```

**父子关系必须一致**：`/projects/A/workspaces/B` 这种组合若 `B.projectId !== A`，直接 404，不返回任何数据。

**设置分层**（不一次大拆，用「项目覆盖 ⊕ 全局默认」的兼容策略）：

| 层 | 内容 | 说明 |
|---|---|---|
| 项目级 | `delimiter`、`defaults`（模型/画幅/分辨率/时长/…） | 存 `project.settings`，未设的项自动回落全局 |
| 系统级 | `queue`（Worker 总并发）、`adapter`（CLI 登录态/版本） | CLI 账号是整机一份，不复制到每个项目 |

**删除策略**：项目与工作区第一版一律**软删除**（打 `deletedAt`），不做级联物理销毁 —— 分镜、素材、生成记录都完整保留，记录靠**生成时刻的名称快照**继续正确显示"当时属于哪个项目/分镜表"。存在排队中/生成中/`submitting` 的任务时禁止删除。

**新增接口**（旧接口全部保留，因此是向后兼容的 MINOR 升级）：

```
GET/POST         /projects                    项目列表（含工作区数/资产数/分镜数）/ 创建
GET/PATCH/DELETE /projects/:id                详情 / 改名 / 软删除
GET/POST         /projects/:id/workspaces     分镜表列表 / 新建
GET/PATCH/DELETE /workspaces/:id              详情 / 改名 / 软删除
GET              /projects/:id/assets         项目资产
GET              /projects/:id/records        项目记录（支持 workspaceId 过滤）
GET/POST         /workspaces/:id/storyboards  工作区分镜
```

**界面层级**（UI 上叫「项目 / 分镜表」，代码内部是 `Project` / `Workspace`）：

```
首页（项目列表）→ 项目主页（分镜表列表 + 资产库 + 生成记录 + 项目设置）→ 工作区视图（分镜表本身）
```

- **首页** `/`：项目卡片墙，每张显示分镜表数 / 分镜数 / 素材数 / 最近修改；可创建、重命名、软删除。
  新建项目时输入框会**预填一个默认名**（`新项目`，重名自动加序号），创建后**留在列表**，不自动跳进项目。
- **项目主页** `/?project=pj_x`：四个**内容页签**，切换时页面头与导航栏保持不动，只换下方内容 ——
  **分镜表**（列表，新建 / 重命名 / 软删除）、**资产库**（项目级，6 类分类 / 搜索 / 上传）、
  **生成记录**、**项目设置**。后两者是**就地**嵌进来的（复用既有的记录视图与设置面板，
  不重做一套），从控制台顶栏打开时它们仍是原来的整屏 / 抽屉形态。
- **工作区视图**：就是既有那张分镜表。顶部面包屑显示「首页 › 项目 › 分镜表」，可逐级返回。
- **刷新恢复**：URL 带 `?project=…&workspace=…`，刷新回到原处；指向已删除对象时逐级安全降级，不会崩。
- **层级转场**：首页 → 项目 → 分镜表以轻量定向动画推进，返回时反向退回；开启系统“减少动态效果”时自动取消动画。
- **窄窗口适配**：首页、项目页与分镜表页在 360px 宽度下仍保留全部操作入口；顶部操作、项目摘要与分镜表卡片自动换行，主表格保留横向滚动以避免列内容被压缩到不可读。
- **切换即清理**：切换项目/分镜表会清空勾选、筛选、搜索、弹层、预览与所有中间态，并给轮询打**代际令牌**
  丢弃过期响应 —— 避免"在 A 表勾的分镜提交到了 B 表"这类串线。

> 新建项目**不会**自动创建分镜表（按用户要求）：建完是空的，自己建第一张即可开始做分镜。
> 反过来，删掉最后一张分镜表也是允许的 —— 空项目是合法状态，随时可以再建。
> 新建分镜表时会预填 `新分镜表`；当前项目内已有同名表时，自动使用 `新分镜表 2`、`新分镜表 3`……。
> 项目下没有分镜表时，分镜相关操作会**明确报错**（而不是静默返回空列表），免得被误读成「这张表是空的」。

## 已知边界

1. **素材删除不可恢复且不留痕**：`DELETE /assets/{id}` 会同时删掉素材记录与磁盘上的图片文件，且**不写 `records` / `logs`** —— 误删后无法查证是谁、何时删的。`db.json.bak-*` 轮转备份只保得住记录，保不住图片（重新启用须重新上传原图）。
2. 真实生成的 CLI flag 在运行时由 `model list` 实时规格解析（禁止硬编码未验证 flag）。
3. 取消运行中任务只能停止本地跟踪（CLI 无取消命令），即梦侧照常计费。
4. 分页控件未做（接口签名已按契约实现）；无鉴权流程（`token` 由 `APP_CONFIG` 注入，401 只 Toast 不跳登录）；无虚拟滚动（大数据量建议用紧凑视图）。
5. 本地 API 的跨域已收窄到**本地 Origin**（详见「版本」一节的 0.2.0 变更）；`Origin: null`（file:// 打开发布版）默认放行，可用 `JC_ALLOW_FILE_ORIGIN=0` 关掉。
6. **发布版（`dist/` 单文件）用 `file://` 双击打开时，现代 Chrome 会拦掉它对本机后端的请求**（2026-09-20 实测发现，与任何改动无关）：页面里 `fetch('http://127.0.0.1:8787/api/v1/...')` 直接抛 `TypeError: Failed to fetch`（127.0.0.1 与 localhost 都一样，请求根本没发出去），界面显示「网络异常，请确认后端已启动」。
   - 判据：`app/api.js`（网络层）逐字节未改；同一份 `dist` 在放宽 web 安全的浏览器里能正常加载 16 条分镜；服务端 CORS 本身允许 `Origin: null`（该请求根本没到达服务端）。
   - **推荐用法仍是 `node server/index.js` 后打开 `http://127.0.0.1:8787/`**（同源，不受此限制）。发布版单文件适合分享/存档，本地直开需要浏览器放宽限制或改由本地服务托管。
