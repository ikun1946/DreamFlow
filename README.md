# 即梦批量生成控制台

设计稿落地为可运行的前端应用。**不需要后端、不需要构建**——双击 `app/index.html` 就能跑。

本目录是**项目的唯一根目录**，设计文档、开发版源码、发布版产物、历史原型全部收敛在这里。

---

## 目录规划

```
jimeng-console/                      ← 项目根。所有文件都在这一层之下，不外溢
│
├── README.md                        ← 你在这里。项目总览、路径导航、联调指引
├── build.js                         ← 构建脚本：把 app/ 内联成 dist/ 单文件版
│
├── docs/                            ← 文档：交付给后端 / 团队阅读的材料
│   └── 前端页面与接口对接说明.md      主交付文档（23 个接口契约、字段表、错误码、三态）
│
├── app/                             ← 开发版：直接改代码的地方（零构建，双击即跑）
│   ├── index.html                   入口页面（页面骨架）
│   ├── styles.css                   全部样式 + 设计令牌（:root）
│   ├── api.js                       ★ 接口层：23 个接口的 mock / http 实现
│   └── app.js                       状态、渲染、交互、轮询
│
├── dist/                            ← 发布版：由 app/ 构建而来，不要手改
│   └── 即梦批量生成控制台.html        单文件版（CSS/JS 全内联，约 110 KB，零依赖，适合分享）
│
└── legacy/                          ← 归档：已被取代的历史产物，确认无用可整目录删除
    └── jimeng-batch-studio.html     第一版深色控制台原型（已被表格版设计稿取代）
```

**路径约定**（改代码 / 加文件时照着来）：

| 规则 | 说明 |
|---|---|
| 源码只进 `app/` | 应用运行时只用这四个文件，互相之间是**同级相对路径**引用，整体挪动不会断链 |
| 产物只进 `dist/` | 由 `app/` 拼装生成，不手改；重建用根目录的 `node build.js` |
| 文档只进 `docs/` | 面向人的阅读材料。新增接口相关文档一律放这里 |
| 废弃只进 `legacy/` | 不直接删，先归档。`legacy/` 为空时即可删除整个目录 |
| 目录名用 ASCII | `app` / `docs` / `dist` / `legacy` 保持英文，规避各类工具链的中文路径问题；**文件名**可以用中文 |
| 根目录只留两文件 | `README.md` + `build.js`。其它任何文件都按上面的规则归位，不要堆在根目录 |

> 运行应用**不需要** `docs/`、`dist/`、`legacy/`。要把应用单独拷给同事，只需带走 `app/` 这一个目录。

## 快速开始

```bash
cd jimeng-console

# 方式一：开发版（改代码时用）
app/index.html               # 双击打开即可，零依赖、无需构建

# 方式二：发布版（分享给别人时用）
dist/即梦批量生成控制台.html   # 单文件，双击即看

# 方式三：起静态服务（推荐，规避个别浏览器的 file:// 限制）
npx serve app                # 或：python -m http.server 8080 --directory app
```

> **两个版本的区别**：`app/` 是**开发版**，四个文件分层清晰、便于联调和改代码；
> `dist/` 是**发布版**，由开发版内联而成，单文件零依赖。
> **改完 `app/` 里的代码，记得重建发布版**。

打开后是一个模拟项目「雨夜归途」的 8 个分镜，覆盖 **生成中 / 排队中 / 已完成 / 失败** 四种状态，
右侧素材库有 6 个角色、6 个场景、4 个道具。生成中的分镜会**自动推进进度**（模拟引擎每 1.2s 一跳）。

## 切换后端：只改一行

应用与后端的所有耦合都在 `app/api.js` 里。要接真实接口，在 `app/index.html` 引入脚本**之前**加一段配置：

```html
<script>
  window.APP_CONFIG = {
    apiMode: 'http',                          // 'mock'（默认）→ 'http'
    baseUrl: 'https://your-api.com/api/v1',   // 与 docs/前端页面与接口对接说明.md 第 5 章路径一致
    token: '<用户 token>',                     // 会以 Authorization: Bearer <token> 发出
    projectId: 'pj_1'
  };
</script>
```

切到 `http` 后，`app/api.js` 会用 `fetch` 请求真实后端，**请求体、响应体、错误码与 `docs/` 里的文档完全一致**，
`app/app.js` 一行都不用改。若后端返回的信封结构不同，只需改 `api.js` 里的 `httpRoute()`。

> **发布版是构建产物**：`dist/` 里的单文件版已把 `api.js` 内联，改完配置需重新构建才生效。

## app/ 内部结构

| 文件 | 职责 | 什么时候改它 |
|---|---|---|
| `app/index.html` | 页面骨架（顶栏、弹窗、抽屉、弹层容器） | 加页面级容器时 |
| `app/styles.css` | 全部样式。开头的 `:root` 是设计令牌（颜色/尺寸/密度） | 调视觉时 |
| `app/api.js` | **接口层**。23 个接口的 mock 实现 + http 转发 | 后端契约变化时 |
| `app/app.js` | 状态、渲染、交互、轮询。只消费 `Api`，不拼 URL | 改交互时 |

分层原则：**`api.js` 不碰 DOM，`app.js` 不拼 URL。**

### 重建发布版

```bash
cd jimeng-console
node build.js
```

脚本会内联四个文件、写出 `dist/即梦批量生成控制台.html`，并自动校验产物
（`$$` 是否被吞、script/style 块数量、有无残留外部引用），任一不通过就报错退出。

> ⚠️ **两个已踩过的坑，改这个构建流程时务必保留防护**：
> 1. **必须用回调函数形式的 `String.replace`**。字符串替换会把代码里的 `$$` / `$'` / `$&` 当成替换占位符吞掉，
>    产物静默损坏，运行时表现为 `Identifier '$' has already been declared`（这个坑真踩过，产物坏了但构建仍然"成功"）。
> 2. **内联前必须检查脚本里有无字面量 `</script`**。哪怕出现在注释里，浏览器也会在那里提前结束脚本块。
>    `build.js` 已内置这两道校验，改脚本时别绕过。

## 接口覆盖情况

`app/api.js` 里 23 个接口全部有 mock 实现，行为按 `docs/` 里的文档约定：

| 文档约定 | 实现位置 |
|---|---|
| 统一响应信封 + `code !== 0` 视为业务失败 | `ApiError` / `httpRoute()` |
| 列表接口顺带返回 `stats`（避免首屏两次请求） | `GET /storyboards` → `stats()` |
| 轮询**只返回有变化的项**，无变化返回空数组 | `GET /storyboards/progress` 的 `_dirty` 标记 |
| 已完成分镜改时长 → `40900` | `PATCH /storyboards/{id}` |
| 批量改时长部分成功 → `updated[]` / `skipped[]` | `POST /storyboards/batch-duration` |
| 批量提交 → `accepted[]` / `rejected[]` | `POST /storyboards/batch-submit` |
| 运行中删除需 `force` | `POST /storyboards/batch-delete` |
| 自定义分隔符拆分（trim 首尾、丢弃空段） | `splitSegments()` |
| CLI 不可用时禁止提交 → `51001` | `batch-submit` |

**前端侧**按文档实现的部分：

- **轮询退避**：基线 3s（mock 下 1.2s），连续 3 次无变化 → 6s → 10s 封顶；异常时指数退避封顶 30s
- **页面隐藏暂停**：`visibilitychange` 为 hidden 时停轮询，恢复时立即拉一次
- **进度平滑**：进度条宽度带 350ms 线性过渡，服务端跳变时视觉不跳
- **乐观更新 + 回滚**：改时长立即生效，`PATCH` 失败回滚原值并 Toast
- **300ms 合并提交**：连点步进器只发一次 `PATCH`
- **四态齐全**：骨架屏 / 空态 / 错误态（带重试）/ 降级
- **枚举不硬编码**：全部来自 `GET /meta/options`，后端加模型前端零改动

| 项 | 设计稿 | 应用 | 原因 |
|---|---|---|---|
| 行高 | 210px | 210px，另提供**紧凑视图**（132px） | 一屏 4 行不适合真实几十条数据，顶栏「紧凑视图」可切 |

## 已实现交互清单

**P1 主界面**
- 勾选 / 全选（底部状态栏出现「批量改时长 / 删除所选 / 取消选择」）
- 时长步进器：`−` / `＋` 逐秒增减（到边界自动置灰）
- 时长直接输入：**双击数值** → 输入框，Enter 提交、Esc 取消
- 时长预设：**单击数值** → 下拉 `5s / 10s / 12s / 自定义秒数…`
- 已完成分镜：时长**锁定**，点击提示「修改时长需重新生成」
- 素材绑定：点表格 `＋` 槽位 → 面板自动切到对应分类 → 点素材卡即可添加
- 素材解绑：悬停缩略图右上角 `×`
- 行操作：上移 / 下移 / 取消 / 重试 / 详情（CLI 命令 + 执行日志）/ 删除
- 批量提交（右侧面板）、搜索、状态筛选
- 详情弹层含**将要执行的 CLI 命令**回显

**P2 批量导入**
- 粘贴 → 防抖 400ms 自动按分隔符拆分
- 分隔符：换行符 / `;;` / `|` / `---` / 自定义（可输入任意字符）
- 实时预览 + 重复标注 + 「已识别 N 段，将创建 N 个分镜」
- 导入后新行自动勾选，可直接批量提交

**P3 设置**
- 分隔符（与 P2 同源数据，这里改 = 以后都这么切）
- 默认模型 / 画幅 / 分辨率 / 时长
- 并发数步进、失败自动重试开关
- 适配器 Mock / CLI 模式切换 + CLI 不可用警告卡
- 恢复默认、保存

## 已知边界

1. **素材上传未实现**（`POST /assets/upload` 抛错），文档里标注为预留接口。
2. **分页控件未做**，接口签名已按文档实现。
3. **无鉴权流程**，`token` 由 `APP_CONFIG` 注入；401 时应用只 Toast，不跳登录。
4. **未做虚拟滚动**。数据量大时建议按文档第 9 章启用，或先用「紧凑视图」。
5. `prompt()` / `confirm()` 用的是浏览器原生弹窗——正式实现应换成设计系统内的弹层。

## 联调建议

后端起来后，按这个顺序验证最快：

1. `GET /meta/options` → 页面能正常渲染出模型名与时长范围（拿不到会卡在骨架屏）
2. `GET /storyboards` → 表格出数据，顶栏 chip 与底部统计正确
3. `POST /storyboards/import/preview` → 导入弹窗能识别出段数
4. `POST /storyboards/import` → 新行出现
5. `POST /storyboards/batch-submit` → 返回 `accepted` 后应能观察到 `GET /storyboards/progress` 被周期性调用
6. 把 `queue.concurrency` 调到 1，确认轮询在有变化时不会退避、无变化时才退避
